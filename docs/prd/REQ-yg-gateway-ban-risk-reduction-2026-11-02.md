# YG Gateway 封号风险降低 — 需求分析（PRD 级）

> 十阶段流水线阶段 1 output。基线：2026-11-02 工作区，账号池 4 个账号。
> 触发原因：面板"模型锁池"出现 `nonexistent-model-xyz`，担心账号被上游风控关联封禁。
> 调研来源：当日生产事故复盘 + 多账号网关风控通用实践。

---

## 必要性

> 补写说明（2026-11-02）：原 PRD 缺阶段 0 必要性段，`scripts/pre-commit.ps1` 检查 8
> （`check-req-necessity.ps1`）判 FAIL。本段事实取自本文档上方「触发原因」与当日生产观测，
> **未新增推断**；未观测到的部分标 unknown。

**1. 要解决的真实问题是什么？**

生产面板「模型锁池」出现 `nonexistent-model-xyz`（observation：面板可见的负缓存条目）。
该模型名不可能来自正常客户端配置，说明有请求带着拼错/伪造的模型名打到了上游，并被网关
写进了 11102 负缓存（6h）。同一份观测还暴露两条：`X-Session-ID` 按 uid 固定派生（跨重启
不变，与真实客户端"每次启动新会话"的行为不符），以及回归脚本 S4/S5.3 直接打生产 7863。

**2. 不做会怎样？**

- 负缓存被任意模型名污染 → 面板冷却显示失真 + 选号槽位被无效条目占用（**可见**，危害中）；
- 固定 Session-ID + 全部账号同 IP 出站 → 上游风控有可关联特征（**不可见**，危害高：
  账号被封是不可逆损失，且**不报错**）；
- 回归脚本打生产 → 每次回归都在生产上制造 429 冷却与假模型负缓存（**可见**，危害中）。

**3. 现状是否已变？**

未变：R8 约束（上游协议数据不改名）与单二进制零依赖仍成立，故本需求只动**出站时序与
身份形态**，不动报文内容。`minRequestInterval`（F-005）此前**不存在**（本次新增）。

**4. 有没有更便宜的等效手段？**

有更便宜的**局部**手段（只清负缓存 / 只改脚本），但解决不了「同 IP 多账号 + 固定会话 ID」
这条风控特征——那需要 per-account 出口（F-004），无法用配置绕过。

**结论：做（已落地）。** 五项 F-001~F-005 全部实施；验收与回滚见下文第三、四节。
重评条件：若上游风控不再按 IP/会话关联（外部行为变化，当前 **unknown**，需实测才能判断），
F-004 的 per-account proxy 可降级为可选能力。

## 一、范围边界

### 做什么

1. **Session-ID 改成进程级随机**（F-001）：原来 `X-Session-ID` 按 uid 固定派生，
   跨重启不变。真实客户端每次启动会生成新会话 ID，固定 Session-ID 像机器人。
2. **11102 负缓存白名单**（F-002）：任何不存在的模型名（包括客户端拼错的）都会被
   缓存 6h，污染面板冷却并浪费选号槽位。已知模型才写负缓存。
3. **回归测试脚本不再污染生产**（F-003）：S5.3 发假模型名触发 11102 负缓存，
   S4 21 连发 RPM 测试故意打上游 429 冷却，硬编码打生产 7863。
4. **per-account proxy 完整链路**（F-004）：4 个账号的请求全部从网关机器同一个 IP 发出，
   上游风控很容易关联"这个 IP 上有 N 个账号在活动"。每账号可配独立代理出口。
5. **最小请求间隔限流**（F-005）：单账号短时间打太密触发上游风控，
   选号时距上次请求小于该间隔的账号跳过。

### 不做什么（明确排除）

1. **不改上游协议报文**（R8 红线）：`wb2api-<ms>` conversationId、`chatcmpl-wb2api` 哨兵、
   三段式 UA 指纹都不动。
2. **不动鉴权**：`api_key` 走 `httpauth` 常量时间比较，已正确。
3. **不做多租户 / 计费**：本项目是个人网关，不引入配额派发。
4. **不引入额外中间件依赖**：保持单二进制零依赖。

## 二、功能需求

### F-001 Session-ID 进程级随机

**需求**：网关重启后生成新的 `X-Session-ID`，模拟真实客户端每次启动新会话。

**Given**：网关进程启动
**When**：生成出站请求头
**Then**：`X-Machine-ID` 按账号固定（模拟一台设备一个号），
        `X-Session-ID` 为本次进程启动时生成的 UUID，重启即换。

### F-002 11102 负缓存白名单

**需求**：客户端拼错模型名不污染面板冷却。

**Given**：上游返回 11102 模型不存在错误
**When**：网关应用错误策略
**Then**：先查 `isKnownModel()` 白名单——已知模型才写负缓存，
        未知模型（包括拼错的）直接透传不缓存，不污染选号槽位。
        目录为空（刚启动）时不写缓存，宁可多试一次，不可误缓存真实模型。

### F-003 回归测试脚本不污染生产

**需求**：手动回归测试不污染生产面板和账号冷却。

**Given**：运行 `python scripts/yg-regression-test.py`
**When**：S5.3 发假模型名、S4 21 连发 RPM
**Then**：① 加 `--base` 参数可切换测试端口；
        ② S4 默认 skip（需显式开启才跑）；
        ③ S5.3 发完假模型名后，主动从 `state.json` 清理冷却条目。

### F-004 per-account proxy 完整链路

**需求**：每个账号可配独立 HTTP/SOCKS5 代理出口，避免多账号同 IP 被关联。

**Given**：auth 文件里配了 `"proxy_url": "socks5://user:pass@proxy:1080"`
**When**：该账号的出站请求
**Then**：走对应代理出口；空 = 直连（默认行为，向后兼容）。
        代理解析/初始化失败时打 WARN 日志，自动回退直连。

**覆盖路径**：聊天主路径 + doJSON 通用请求（12 个调用点）+ 模型目录拉取 + global 模型目录。

### F-005 最小请求间隔限流

**需求**：单账号请求间隔不小于配置阈值，避免短时间打太密。

**Given**：config.json 里配了 `pool.min_request_interval: "1500ms"`
**When**：选号时检查账号
**Then**：距上次请求小于该间隔的账号跳过；
        global 域用 `min_request_interval_global` 分档（国际版风控更敏感）；
        默认 `"0"` = 关闭（零回归）；
        全池被间隔限制时，选最早恢复者，不 503（和 failureWindow 同哲学）。

## 三、验收标准

| 验收项 | 验证方式 |
|---|---|
| F-001 Session-ID 重启即换 | 重启网关后抓包对比两次 `X-Session-ID` |
| F-002 拼错模型不污染冷却 | 发 `nonexistent-xyz` 后看面板冷却无新增条目 |
| F-003 回归脚本可切端口 | `--base http://127.0.0.1:7864` 打测试端口 |
| F-004 per-account proxy | 配 socks5 后抓包确认走代理出口 |
| F-005 最小请求间隔 | 配 `1500ms` 后连发请求，观察选号间隔 |
