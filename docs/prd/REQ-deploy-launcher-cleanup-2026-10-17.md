# REQ — 回收 launcher（cmd.exe）：失败换版不留孤儿

- 状态：已实施（2026-10-17）
- 分级：**L2**（改生产换版脚本的行为；回滚路径受影响）
- 来源：`docs/PLAN-open-items-2026-10-17.md` §9.3 **B4b**；`scripts/deploy-prod.ps1` 文件头「已知边界」
- 相关纪律：R15（换版前备份）、L-9（等端口释放）、L-12（非 PE 当 exe 启动会卡住 launcher）

## 必要性

**①真实问题**：`Start-Instance` 用 `Start-Process cmd /c "<exe> -config … > log 2> log"` 借 cmd 做重定向。
启动失败（健康不过 → 回滚，或回滚也失败）时，这个 cmd **没有人收**：它一直握着重定向文件的句柄，
脚本退出后变成孤儿；下一次换版也认不出它，于是**逐次累积**（B4b 记录的现象）。

**②不做会怎样**：不报错、不影响功能（改名替换让旧 inode 摘链），但两个实际后果：
①失败现场日志被活着的进程握着，回滚后想读 stderr 会读不全；
②进程表里堆 `cmd.exe`，下一次真出事时很难分辨哪个是"自己的"。

**③现状是否已变**：没变。`deploy-prod.ps1` 里没有任何 launcher 回收逻辑
（`Select-String 'launcher|Stop-Launcher'` 在本次改动前零命中）。

**④更便宜的等效手段**：有，而且比 B4b 原建议（"按命令行含目标 exe 且父进程已死"清理）**更精确**：
`Start-Instance` 的 `Start-Process -PassThru` 直接给出 launcher PID → 启动失败时按**精确 PID** 回收，
误杀面为 0。命令行启发式只留给"历史遗留孤儿"的启动前清扫。

**结论：做（L2）**。收益是"失败现场可读 + 进程表不累积"，成本约 45 行，且不影响成功路径。

## 一、目标与非目标

**目标**：①启动失败时回收本次 launcher（精确 PID）；②换版开始时清扫**以前**留下的孤儿
（三条判据同时成立才杀）；③两种情况都不静默（要么打印回收了谁，要么打印为什么没杀）。

**非目标**：不清理**其他**程序的 cmd.exe（含操作者手开的、其他工具的）；不改启动方式
（cmd 重定向的理由见 `Start-Instance` 注释：`-RedirectStandardError` 会把 stdout 一起吞掉）；
不动回滚语义与退出码表。

## 二、验收（Given-When-Then）

### F-1101 — 失败启动的 launcher 被精确回收

- **Given** 新实例健康检查不过，进入回滚分支
- **Then** 回滚**前**先按本次 launcher PID 回收（`Stop-Launcher`），日志出现
  「失败的新实例 launcher：已回收 launcher PID …」
- **Given** 回滚实例也不健康
- **Then** 同样回收回滚 launcher（否则它成为下一次的孤儿）

### F-1102 — 孤儿清扫只杀「历史上没人管的」

- **Given** 存在一个 `cmd.exe`：命令行含目标 exe 完整路径，且其父进程**已不存在**
- **Then** 换版进入 2/6 前被回收并打印 PID 与死掉的父进程号
- **Given** 同样的 cmd 但其父进程**还活着**（本次运行自己的 launcher，或操作者会话）
- **Then** **不杀**（`killed=0`），进程保持存在
- **Given** 命令行不含目标 exe 的 cmd
- **Then** 不杀

### F-1103 — 成功路径零影响

- **Then** `-DryRun` 与正常换版的步骤/退出码/报告字段不变；成功路径不打印任何回收日志
  （孤儿清扫命中 0 个时不输出）

## 三、决策

| # | 决策 | 选择与理由 |
|---|---|---|
| D-1 | 回收用精确 PID 还是命令行启发式 | **失败现场用精确 PID**（`-PassThru` 拿到的，误杀面 0）；启发式只用于启动前清扫历史孤儿，并要求"父进程已死" |
| D-2 | 清扫放在哪一步 | **2/6 停旧实例之前**：孤儿可能握着上次的日志句柄，且晚于停服会让端口判定更难读 |
| D-3 | PID 被复用怎么办 | 回收前核 `ProcessName`，不是 `cmd` 就**不杀**并说明原因（R10 不静默） |

## 四、影响分析

| 文件 | 改动 |
|---|---|
