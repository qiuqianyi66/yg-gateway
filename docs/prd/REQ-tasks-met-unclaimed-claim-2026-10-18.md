# REQ — 「达标未领」两条入口统一为「去领奖」（A7 / D3）

- 状态：已确认（用户 2026-10-18 批准 A-2，选定「入队去领」）
- 日期：2026-10-18
- 分级：**L2**（改的是奖励领取行为：一类任务从「领不到」变成「领到」）
- 来源：`docs/PLAN-next-2026-10-18.md` A-2；`docs/PLAN-open-items-2026-10-17.md` A7 / D3

## 一、必要性

同一个账号状态（任务已达 target、未领取奖励）在两条入口下结果相反：

| 入口 | 旧行为 | 后果 |
|---|---|---|
| 扫描入队（`growthPending` → `runGrowthQueued`） | 入队 → 先跑一次动作 → 再领奖 | **领到**，但白跑一次动作（上游回「无需上报」） |
| 一键完成（`runAutoAll`） | `before.Claimed \|\| Current >= Target` → `skipped` | **领不到**，且判定文案写「已完成」 |

用户点「一键完成全部可自动任务」时，恰恰是最需要把奖励一次收干净的场景，而被跳过的正是
**已经做完、只差点一下领取**的任务。这不是统计口径差异，是**积分实实在在没入账**——
与 Product Direction「养号友好 / 积分不浪费」直接冲突；而两条路径都不报错，运维看不出差别。

代码层还有一个更硬的事实：`growthPending` 的达标分支与兜底分支**返回同一个表达式**：

```go
if t.Target > 0 && t.Current >= t.Target {
    return autoActionFor(t.TaskCode) != nil   // ← 与下一行等价
}
return autoActionFor(t.TaskCode) != nil
```

也就是说「达标未领」在入队判定里**零差别**（死分支），真正的分歧只发生在两条执行路径里。

**不做会怎样**：每天都有一批「已完成但没领」的任务，取决于运维点了哪个按钮，奖励领不领到不确定。

**更便宜的等效手段**：无。这是把两份判定收敛成一份，并让两条路径都执行「领奖」这一个动作。

## 二、目标与非目标

**目标**：`disposeTask(t)` 成为唯一判定；两条入口都只执行它的结论：

| 状态 | 处置 | 入队 | 一键完成 |
|---|---|---|---|
| 已领取 / 锁定 / 无自动化动作 | `taskSkip` | 不入队 | `skipped` |
| 未达标 | `taskRun` | 入队跑动作 | 跑动作（回读 claimable 后领奖） |
| 达标未领 | `taskClaim` | 入队**只领奖** | **只领奖** |

**非目标**：

- 不改「谁算达标」（仍由上游 `Task.Current/Target/Claimed` 决定）；
- 不改 mp 任务的领奖口径（仍走 chat 域 + `X-Client-Platform: miniprogram`，只是收敛到一个函数）；
- 不改队列并发与节流参数；不改云控/账号门控。

## 三、验收（Given-When-Then）

**F-A7-a 达标未领两条入口都领到奖**
- Given 任务 `chat_5` `5/5` 且未领取
- When 分别执行 `runAutoAll` 与该任务的队列执行
- Then 两条路径都**恰好领奖 1 次**，且 `claimed=true`

**F-A7-b 达标未领不再白跑动作**
- Given 同上
- When 任一路径执行
- Then 该任务**没有** `/v2/report` 动作上报（旧行为会先跑一次动作）

**F-A7-c 已领取 / 未达标不受影响**
- Given 任务已领取，或未达标（`1/5`）
- Then 两条路径都**不领奖**（`1/5` 只跑动作；已领取直接跳过）

**F-A7-d 判定只有一份**
- Given 任意任务形态
- Then `growthPending(t) == (disposeTask(t) != taskSkip)`，且 `disposeTask` 表格逐条钉住

## 四、影响分析

| 面 | 影响 |
|---|---|
| 积分 | 「一键完成」会多领到一批此前被跳过的奖励（方向正确，量取决于待领任务数） |
| 上游调用 | 达标未领的任务**少一次**动作上报（不再白跑），多一次领奖请求 |
| 队列 | 达标未领项的执行时间从「动作 + 回读轮询 + 领奖」降到「领奖一次」 |
| mp 口径 | 不变：`claimRewardFor` 仍是 `ClaimRewardMP`（chat 域 + mp 头），有测试钉住 |
