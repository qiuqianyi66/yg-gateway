# YG Gateway 面板体验与工程规范化 — 需求分析（PRD 级）

> 十阶段流水线阶段 1 的 output（`.harness/rules/开发流程规范.md` §一）。
> 模板来源：`docs/prd/_template/requirements-template.md`（自 tea 项目 harness 移植）。

## 一、范围边界

### 做什么

1. 建立 `.harness/` 治理体系（rules / wiki / changes / skills），把开发流程从"随手改"变成"十阶段可追溯"。
2. 按 tea 模板重做需求分析文档（本文件），产出 F-编号 + Given-When-Then 验收 + D-编号决策点。
3. 面板前端视觉与交互重做：从"功能堆砌的后台"转为"一眼读懂的仪表盘"。
4. 建立设计令牌基线与反模板约束（对齐 `frontend-design-spec` 的"一眼认不出是模板/AI 生成"）。

### 不做什么（明确排除）

1. **不动上游协议与出站报文**：conversationId 形态、UA、指纹头一律保持（R8 红线，改动有风控风险）。
2. **不动选号/冷却/熔断核心算法**：这些是承重墙，本次只改展示层，不动池逻辑。
3. **不引入前端构建链**（Vite/Tailwind/框架）：面板是 `go:embed` 单文件，引入构建链会破坏"单文件自包含"这个核心优势。
4. **不做移动端适配**：当前是本机单人使用，桌面优先（仓库里已有 #144 是他人的移动端 PR，不重复立项）。
5. **不改 API 契约**：`/v1/*` 与 `/panel/api/*` 的路径、字段、鉴权口径一律不动，前端只读消费。

| F-编号 | 需求 | 优先级 |
|---|---|---|
| F-001 | 建立 `.harness/` 治理骨架：rules（流程/结构/编码）+ wiki（业务/数据/契约/术语）+ changes 模板 | P0 |

| F-003 | 面板视觉重做：统一设计令牌、重构信息层级、消除模板感 | P0 |

### 验收标准（Given-When-Then）

- **F-001**：Given 项目根目录 / When 执行 `ls .harness/` / Then 存在 `rules/`、`wiki/`、`changes/_template/`、`skills/` 四个目录，且 rules 下含开发流程/工程结构/编码三份规范
- **F-002**：Given 任意新需求 / When 提出改动 / Then 先产出 `docs/prd/*.md` 含 F-编号与 Given-When-Then，经确认后才进编码；禁止直接改代码
- **F-003**：Given 打开面板 `/panel/` / When 浏览各视图 / Then 视觉语言统一（令牌驱动、无裸色值）、首屏能回答"池子健康吗 / 积分够吗 / 什么时候到期"
- **F-004**：Given 4 个账号且都有到期批次 / When 打开账号池页 / Then 无需点任何按钮即可看到每个号的最近到期日、该批数量、日均需耗
- **F-005**：Given 完成一次改动 / When 提交前 / Then `.harness/changes/{feat}/summary.md` 已写，含变更概览/需求与方案/影响分析/自检清单
- **F-006**：Given 出现术语歧义 / When 查阅 `wiki/glossary.md` / Then 能查到 canonical 定义，且与代码实际行为一致

### Spec 门禁（硬约束）

1. 单切片 Spec ≤100 行（本文档正文约 95 行，符合）。
2. L2 级需求（F-001/F-002/F-005）必须有可验证产出物；L1 级（F-003/F-004）以视觉冒烟为准。
3. 代码生成后 >10 轮人机返工 → 回需求阶段重新对齐 Spec。

## 三、非功能约束

- **性能**：面板首屏不打上游（既有约束，F-004 必须用 `/overview` 快照实现，零新增请求）
- **安全**：视觉改动不得引入内联脚本/内联事件（CSP `script-src 'self'`）；所有插值继续走 `esc()`
- **兼容**：保留明暗双主题；`go:embed` 单文件特性不变，改前端必须重编译
- **可观测**：改动后 `/healthz` 仍返回 `service=yg-gateway`，`/status` 字段不变
- **成本**：不引入任何新依赖（当前仅 12 个模块，保持）

## 四、影响分析

- **影响面**：`.harness/`（新增）、`internal/panel/index.html` + `app.js`（前端重做）、`docs/`（新增）
- **承重墙**：❌ 不触及选号/冷却/熔断/凭证链路/出站改写管线——本次纯展示层 + 治理层
- **契约变化**：❌ 无。`/v1/*` 与 `/panel/api/*` 全部不变（wiki/api-contract.md 无需改动）
- **回滚路径**：二进制备份（`yg-gateway.exe.v2.0.0`）+ git 提交可回退；`auths/` 不参与回滚
- **风险**：前端改动需重编译才生效（R13），冒烟时必须用新二进制验证，不能只看源码
