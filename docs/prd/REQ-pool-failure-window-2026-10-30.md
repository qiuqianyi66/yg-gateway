# REQ-pool-failure-window-2026-10-30 — 账号级故障窗（P0-2）

## 必要性

1. **要解决的真实问题（观测）**：单次失败（上游超时/连接错误/未知 4xx）后账号立即
   回到选号候选——EWMA alpha=0.1 对单次失败权重几乎不变，连败降权需满 5 次才触发
   出池。抖动中的账号会被下一请求立刻再次选中，连续被打直到连败满阈值（OpenRouter
   30s 故障窗正是消解此形态）。
2. **不做会怎样**：瞬时故障号在抖动期持续接新请求 → 请求重复失败、TTFB 恶化、
   EWMA/熔断信号被反复污染；后果可见（请求失败）但根因隐蔽（选号不读最近失败时刻）。
3. **现状是否已变**：10-30 全天命中率 95.8% 已闭环缓存主线，失败路径无回归风险；
   本项是调研对齐 P0-2 的独立增量，与缓存修复正交。
4. **有没有更便宜的等效手段**：无——现有冷却（需权威错误码）、熔断（需反复失败）、
   连败降权（需满阈值）都不覆盖"单次失败即短窗避让"；直接复用已记录的 lastErr
   （零新增持久化）。**结论：做**（默认 30s，config "0" 可关 = 零回归）。

## 背景

大型中转平台对齐调研（OpenRouter / LiteLLM / new-api）结论 P0-2：在 EWMA 之上叠加
「最近 N 秒故障排除窗 + 429 后短冷却（秒级）」，冷却单位是单个账号。

yg-gateway 现状盘点：

| 机制 | 现状 | 缺口 |
|---|---|---|
| 429 短冷却 | CooldownSoftRate（对齐重置墙钟/有界退避） | 已覆盖 |
| 熔断 | 反复 5xx → 指数退避（3 次起） | 已覆盖 |
| 连败降权 | 未知失败 5 次连败 → 10min 出池 | 需累积 5 次，单次失败无短期避让 |
| EWMA 加权 | 成功率/延迟回灌权重（alpha=0.1） | 对瞬时故障响应太慢，一次失败权重几乎不变 |

**缺口**：单次失败（超时/连接错误/未知 4xx）后账号立即回到候选，EWMA 权重几乎
不变、连败降权又需 5 次才触发——抖动中的账号会被下一请求立刻再次选中，连续被打
直到连败满阈值。这正是 OpenRouter 30s 故障窗要消解的形态。

## 需求

新增**账号级故障窗**：账号最近一次失败（NoteError / NoteFailures 喂入的 lastErr）
落在窗口内时，该账号**临时退出 normal 选号候选**；窗口自然过期后自动回池。

### 行为契约（Given-When-Then）

- GIVEN 池配置 `pool.failure_window` 为默认值（"30s"）
  WHEN 某账号刚发生一次失败（任意类别）
  THEN 该账号在接下来 30s 内不被 normal 选号选中（PickExcluding* 排除）
- GIVEN 同一账号已失败且距失败超过窗口
  WHEN 再次选号
  THEN 该账号回到候选（窗口自然过期，无需显式复位）
- GIVEN 全部非禁用账号都落在故障窗内
  WHEN 选号
  THEN 走既有 pickEarliestExpiry 兜底（捞最早到期者，不产生 503 新语义；
       失败成本仅一轮换，与现有兜底哲学一致）
- GIVEN 配置 `pool.failure_window` 为 "0"
  WHEN 账号失败
  THEN 不产生任何避让（零回归，与改动前逐位一致）
- GIVEN 账号处于冷却/熔断/连败降权期
  WHEN 故障窗判定
  THEN 窗判定不改变三者语义（healthy 或门不变，取更长者仍由既有机制保证）

### 显式不做的（防屎山）

- 不新增持久化字段：复用 lastErr（已有，NoteError 已喂；补 NoteFailures 喂入）
- 不新增 Status 字段：LastErrTime 已透出，运维可从面板读最近失败时刻
- 不进 healthy()：故障窗只挡 normal 候选；healthy() 同时被兜底/粘性路径复用，
  加进去会让全池窗内时兜底也失效（行为退化）
- 不做成功清窗：窗口短（30s），失败-成功交替的抖动号不应绕过窗口（与
  OpenRouter 语义一致）；全池皆窗内时由兜底兜住

## 验收（Given-When-Then 落地）

- 单测 `internal/pool/failure_window_test.go`：
  1. 默认（未注入）故障窗 = 关闭 → 失败后立即可选（零回归）
  2. 注入 30s → NoteError 后窗内排除、窗外回池（注入时钟）
  3. NoteFailures 喂入同样触发窗（lastErr 更新）
  4. 全池窗内 → 兜底仍返回账号（非 nil）
  5. 单号池窗内 → 兜底返回该号（不 503）
- config 归一测试：空值回落 "30s"、显式 "0" 关闭、非法时长报错
- 门禁全绿：go test ./... + go vet + gofmt + check-boundaries + check-depth
- 部署：deploy-prod.ps1 -Build，冒烟通过（/healthz、/v1/models、流式+非流式）
