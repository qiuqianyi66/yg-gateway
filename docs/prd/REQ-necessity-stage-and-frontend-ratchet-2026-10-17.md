## 必要性

**①要解决的真实问题**：2026-10-17 这一天的待办清单里 **14 项有 6 项经实测不需要做**、
2 项是"旧文档把已修的事写成遗留"（A9）、1 项收益是可用空间的 0.13%（D4）。直接开工的代价是
「花几小时做一件不该做的事，再花时间回滚」。清单由上一轮的假设写成，假设会过期，而**没有任何
机制要求开工前先验证假设**。

**②不做会怎样**：不是报错，是**持续浪费**——可复算的例子：本轮分析省掉约 2 个工作日的工作量，
只花了约 3 小时。不做这个规范，下一轮会重复同样的浪费，且每次都不报错。

**③现状是否已变**：没有变。`开发流程规范.md` 的十阶段流水线从**阶段 1（需求分析）**起步，
"要不要做"从来没有被列为可交付物；`docs/prd/REQ-*.md` 的既有模板里也没有这一节。

**④更便宜的等效手段**：有，而且本轮就用了——**四个问题 + 一个结论，写一段话即可**，
机器只校验"有没有这一节"（不校验内容质量）。这比"开会评审必要性"便宜，也比"事后回滚"便宜。

**结论：做（L2）**。四问与四结论已写进 `开发流程规范.md`「零、阶段 0」；
新增 `scripts/check-req-necessity.ps1` 接入 `pre-commit.ps1` 作检查 8/8，只对**本次新增**的
REQ 文件生效（存量不追溯，否则第一次接入就会红一片、规则会被绕过）。

## 一、问题（除主诉求外的两项附带走查）

1. **前端体量完全不在门禁内**：`check-depth.ps1` 只扫生产 `.go`（`-Filter *.go`），
   而 `internal/panel/app.js` 是仓里最大的生产文件（**4378 非空行**）——它可以无上限增长
   而不触发任何棘轮（PLAN 的 O1）。
2. **两份测试沙箱靠人记同步**：`internal/pool/main_test.go` 与 `internal/server/main_test.go`
   是手工同步副本，漏同步的那一份会**静默**失去环境隔离（测试照跑，不再隔离）。
   抽公共包已被文件顶部注释明确拒绝（零新依赖 + 边界白名单 + "23 包"口径会漂移）。

## 二、目标与非目标

**目标**：把"动工前先分析必要性"变成**可交付物 + 机器可校验**；把上面两项走查的"静默"变成"会红"。

**非目标（明确不做）**：

- **不校验必要性段的内容质量**（只查小节存在）。判断质量靠评审，不靠正则。
- **不追溯存量 REQ**：只对本次新增的 `docs/prd/REQ-*.md` 生效。
- **不拆 `app.js`**：拆分属结构性改动，且无浏览器级 E2E 兜底（风险 > 收益）。重评条件：出现 Playwright 兜底。
- **不抽 `internal/testenv` 公共包**：理由见两份沙箱文件顶部注释（设计上已拒绝）。
- **不改 `check-boundaries.ps1` 的白名单**（本轮不新增包）。

## 三、验收（Given-When-Then）

### F-1001 — 新增需求文档必须含「必要性」段

- **Given** 本次新增了 `docs/prd/REQ-xxx-2026-10-17.md` 但不含任何 `## 必要性` 形式的小节
- **When** 跑 `scripts/check-req-necessity.ps1`（本地：staged 新增 + 未跟踪；CI：`-Base <ref>` 的新增）
- **Then** 退出码 **1**，打印缺该段的文件与四问模板
- **Given** 含 `## 必要性` / `## 一、必要性` / `### 必要性分析`
- **Then** 退出码 0
- **Given** 本次没有新增 REQ 文件
- **Then** 退出码 0（提示跳过，不误报存量）

### F-1002 — 该检查接入总闸

- **Then** `pre-commit.ps1` 出现「检查 8/8：新增需求文档的必要性段（阶段 0）」，
  失败进 `$failures` 并让总闸 `exit 1`；CI 的 `gate` job（`-Fast -AllFiles -Base <ref>`）
  同样会跑到它（`-Base` 透传）

### F-1003 — 前端体量入棘轮（只许降）

- **Given** `internal/panel/app.js` 为 4378 非空行、基线 `maxFrontendLines = 4378`
- **When** 跑 `check-depth.ps1`
- **Then** 打印「最大前端文件行数 : 4378 (internal\panel\app.js)」，且 `exit 0`
- **Given** 给 `app.js` 加一行
- **Then** `REGRESSED: maxFrontendLines 4378 → 4379`，`exit 1`
- **口径**：非空行（与 .go 口径一致），排除 `node_modules`

### F-1004 — 两份沙箱文件必须同步

- **Given** 两份文件除白名单差异（`package` 行 / 沙箱目录前缀 / 日志前缀 / pool 独有的 `TestMain` 三行）外逐行相同
- **Then** `TestSandboxFilesInSync` PASS
- **Given** 往 `internal/pool/main_test.go` 加一行代码而不同步
- **Then** FAIL，报错指出行号与两侧内容
- **注意**：测试不能靠 `os.Getwd`（`TestMain` 的沙箱已 chdir），必须用 `runtime.Caller` 定位源目录

## 四、决策点

| # | 决策 | 选择与理由 |
|---|---|---|
| D-1 | 必要性段用"机器校验存在"还是"纯人工评审" | **机器校验存在**。只查小节存在，成本 ~60 行；纯人工在第一轮就会被跳过 |
| D-2 | 只查新增还是连存量一起查 | **只查新增**。存量 7 份 REQ 都没有这一节，一起查会让门禁第一次运行就红，规则立刻被绕过 |
| D-3 | 前端纳入棘轮的方式 | **新指标 `maxFrontendLines`**（而不是把 JS 塞进 `maxFileLines`）。后者会让 2058 直接跳到 4378，等于**放宽** `.go` 的棘轮 |
| D-4 | 沙箱同步用重构还是断言 | **断言**。重构被设计明确拒绝（见非目标），断言 25 行且永久有效 |
