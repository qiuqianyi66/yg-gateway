- 日期：2026-10-16
- 来源：`docs/superpowers/plans/HANDOFF-2026-10-16-ci-closed.md` §3 N1、§7 D3；

- 相关纪律：R15（替换二进制前必须备份）、L-1（PS 引号陷阱）、L-3（引号/变量展开）、
  L-10（定点编辑）、L-11（测试与它依赖的生产改动同一提交）

## 一、问题（为什么必须固化，而不是继续写在文档里）

上一轮换版**把生产打断了约 1 分钟**：`stop.bat` 之后只等 2 秒就启动新版本 →
端口仍被旧监听占着 → 新实例没起来 → 30 秒健康轮询超时 → 自动回滚。
同时 `start.bat` 的 `start ... >> data\stdout.log` 根本不落子进程输出
（重定向加在 `start` 自己身上），**新实例起不来时没有任何日志可查**。

这两件事的直接教训（见 L-9）是「轮询端口释放 / 落独立 stderr / 失败自动回滚」。
但它们当时只是**文档里的纪律**，而执行者下次仍会凭记忆做——凭记忆做时漏掉的恰好是
「`taskkill` 返回后监听套接字还没释放」这一步。本需求把它变成一条命令。

## 二、目标与非目标

**目标**：一次调用完成「备份 → 等端口释放 → 替换 → 启动（落日志）→ 健康轮询 → 冒烟 →
失败自动回滚」，且**每一步的判据都是测出来的，不是拍的**；所有中间结论（哈希、备份路径、
日志路径、健康值、冒烟结果）落一份机器可读的 JSON 报告。

**非目标（明确不做）**：

- **不管首次部署**：生产目录里没有 `yg-gateway.exe` 时明确报错并退出，不替人决定怎么初始化。
- **不回滚 `config.json`**：配置变更不在本脚本职责内（它是二进制换版脚本）。
- **不做全模型冒烟矩阵**：一次非流式 + 一次流式足够证明「网关能转发」；模型矩阵是 CI 的事。
- **不做进程清理兜底**：端口被别的进程占着时明确报错，不替人 `taskkill` 陌生进程。
- **不装 git hook、不引入依赖**（零新依赖是定位）。

## 三、验收（Given-When-Then）

### A1 — 候选不是合法 PE：预检在**停服之前**拒绝

- **Given** 生产正跑着旧版；候选 `-Exe` 是一个 33 字节的文本文件
- **When** 运行 `deploy-prod.ps1 -Exe <坏文件>`
- **Then** 退出码 **1**；报告 `stage=rejected-not-pe`、`backup_path` 为空；
  **没有**产生 `.bak`；生产 exe 哈希未变；**没有**产生新实例日志；
  端口上的监听进程 **PID 不变**（= 没停服）。
- **为什么是「拒绝」而不是「回滚」**：非 PE 在读文件头时就能判定，
  没有理由先停服再回滚——「一步都没走」比「走了再退回来」严格。

### A2 — 是 PE 但跑不起来：健康轮询超时 → 自动回滚

- **Given** 生产正跑着旧版；候选 `-Exe` 是合法 PE 但立刻退出（`where.exe`）
- **When** 运行 `deploy-prod.ps1 -Exe <该文件>`
- **Then** 退出码 **2**；报告 `stage=rolled-back`、`rolled_back=true`；
  备份存在且哈希 = 替换前的旧 exe；**回滚日志与失败现场日志是两个文件**；
  生产 exe 已恢复成旧版哈希；服务重新在跑。

### B — 候选正常：替换生效且**不拖死调用方**

- **Given** 生产正跑着旧版；候选是另一个真的能跑的旧构建（哈希与旧版不同）
- **When** 用 `& powershell -File deploy-prod.ps1` **捕获输出**的方式运行（CI / agent 的调用形态）
- **Then** 退出码 0；备份 = 替换前的旧 exe；磁盘上的 exe = 传入的新 exe；
  健康检查通过；新版本在跑；**整个调用在 30 秒内返回**——即使新实例此后常驻。
- **为什么单列**：`Start-Process -RedirectStandardOutput/-RedirectStandardError` 起的常驻
  孙子进程会持有调用方 stdout 管道的写端，用 `&` 捕获输出时会一直阻塞到该进程退出
  （实测：内层 3s 结束、外层阻塞 8865ms）。这条断言就是那个坑的回归测试。

### C — `-DryRun` 不得改动任何东西

- **Given** 生产正跑着旧版
- **When** 运行 `deploy-prod.ps1 -DryRun`
- **Then** 退出码 0；exe 未被替换；**没有**产生备份；**没有**启动任何进程。

### D — 停服之后才失败：**必须把旧版重新拉起来**（独立复审发现的 C1）

- **Given** 生产正跑着旧版；另一个进程以 `FileShare.Read` 独占占着生产 exe
  （改名替换必被拒，但镜像仍可被读取）
- **When** 运行 `deploy-prod.ps1 -Exe <新 exe>`
- **Then** 替换失败；但脚本**不能就这么退出**——必须先确认旧版回到运行状态：
  退出码 **1**（＝本次换版未生效、生产已恢复原状）、报告 `stage=rolled-back`、
  `rolled_back=true`、`rollback_failed=false`、exe 内容未被改坏、**端口有监听且 `/healthz` 有响应**。
  旧版拉不起来时退出码是 **4**（生产可能不可用），**不是 1**。
- **为什么单列**：这条路径原来不可达——回滚只挂在「健康检查失败」分支里，而「停服后替换失败」
  直接 `exit 1`。那时服务已经停了（旧实例被 `taskkill`），退出码却声称「生产未被改动或已恢复原状」。
  那是 L-9 要消灭的「生产停住没人救」换了个触发点，而**回滚是这脚本唯一存在的理由**。

### 机器可读报告（每个场景都验）

- 报告是 JSON，含 `stage` / `exe_hash_before` / `exe_hash_after` / `backup_path` /
  `backup_hash` / `health_ok` / `healthy` / `total` / `rolled_back` / `smoke[]` /
  `log_path` / `rollback_log_path`。脚本**任何**退出路径都会写这份报告（含未预期异常），
  否则「脚本挂在哪一步」只能靠猜。

### 冒烟（生产实弹，不在排练沙箱内）

沙箱没有账号，打真实上游必然失败，所以排练用 `-SkipSmoke`。冒烟三条
（`/v1/models` + 一次非流式 + 一次流式含 `data:`/`[DONE]`）由一次生产实弹覆盖。
冒烟失败**不回滚**：那多半是上游账号/额度问题，回滚会来回折腾；退出码 3 并打印备份路径。

## 五、实施中发现的五个真问题（都不是需求的一部分，是动手才暴露的）

1. **PS 5.1 的 `Invoke-WebRequest` 在非 2xx 时 body 已被读掉**（L-13）：
   健康检查把「服务活着但 0 账号（503）」读成「没有响应」→ 误触发回滚，
   一次刷出 14 项假失败。改为直连 `System.Net.HttpWebRequest`。
2. **覆盖被占用的 exe 会失败，改名替换才会成功**（L-14）：
   坏 exe 的 launcher 占着目标文件时，`Copy-Item` 覆盖式回滚**持续失败**——
   而那正是回滚唯一存在的理由。改为「写 `*.staged` + `Move-Item -Force`」。
3. **把非 PE 当 exe 启动会弹模态对话框**（L-12）：Windows 兼容层弹「不支持的
   16 位应用程序」，`cmd` 卡在等人点确定上；err 日志 0 字节、文件被占住、
   桌面留一个要人手点的窗口。这条直接催生了 A1 的预检。
4. **冒烟判据本身是假的（生产实弹才发现）**：非流式判「`content` 非空」——而目录里第一个
   模型可能是**推理模型**（实测 `cn:auto` → `hy4-preview`），`max_tokens: 16` 全被
   `reasoning_content` 吃掉、`content` 为空但 HTTP 200、`finish_reason=length`；
   流式判「含 `data:` 且含 `[DONE]`」——而 `data: [DONE]` 一行同时满足两者。
   两者都会**放过退化响应或误杀正常响应**。
5. **C1：回滚对「停服之后才失败」这条路径不可达**（独立复审发现，排练场景 D 复现）：
   完整的回滚实现只挂在「健康检查失败」分支里，而「停服后端口没释放 / 替换失败」两条
   直接 `exit 1` —— 那时服务已经停了。修法是把回滚收敛成一个函数、
   **所有**失败分支都走它，并把退出码 `1` 的含义收紧为「已确认旧版在跑」。

1–3 写进 `.harness/LESSONS.md`（L-12/L-13/L-14）；4 只在实弹中可见（沙箱没账号打不了冒烟）；
5 由「落地后一次全新上下文复审」发现。五条都在排练或实弹里各有对应的验证。
