# REQ — 夜猫子末次对话后不再空等 4s（B4a）

## 一、必要性

`RunNightChats`（`internal/upstream/blackcat.go`）每成功一次对话就 `sleepNightChat()`，**含最后一次**：

```go
ok++
c.sleepNightChat()   // need 次成功 → need 次 4s 等待
```

末次成功后循环即结束，后面没有任何请求需要拉开间距。这 4s 是纯空耗：每次夜猫子任务
（`need` 次）固定多付 4s，且这段时间里账号槽位/调度轮次被占着。

旧代码的注释自己写着「含最后一次，与改动前逐位一致（不顺手省掉末次等待：那是另一件事）」——
本条就是做这「另一件事」，不是推翻当时的判断（当时是为了避免把测试提速和行为变更夹在一起）。

**不做会怎样**：不是错误，是持续的可测量浪费——每个夜猫子任务 4s，全账号轮次线性累加；
而 4s 也是 `go test` 的固定成本（R8 golden 生成器与成功路径用例各付一次）。

**现状是否已变**：夜里对话的间隔时长（4s）与「要不要等末次」是两件事；前者是风控观感，
后者没有对应的上游请求，所以本条**只删末次等待，不动时长**。

**更便宜的等效手段**：无。这就是删掉一次无意义等待，改一行。

## 二、目标与非目标

**目标**：等待只发生在相邻两次对话之间，共 `need-1` 次。

**非目标**：

- **不改 `nightChatGap = 4s`**（风控相关，改了是拿观感换速度）；
- 不改 `SetNightChatSleep` 的注入契约（注入函数仍收到生产默认时长，便于断言默认值没被改小）；
- 不改对话内容/模型/上报事件链（R8 报文约束）。

## 三、验收（Given-When-Then）

**F-B4a-a need=1 不等待**
- Given 夜猫子任务 `need=1`
- When 执行 `RunNightChats`
- Then 注入的等待函数**被调用 0 次**，返回 `ok=1`

**F-B4a-b need=3 等 2 次**
- Given `need=3`
- When 执行
- Then 等待**恰好 2 次**，且每次收到的时长都是 `4s`

**F-B4a-c 间隔时长仍受钉住**
- Given 任意 `need`
- Then 每次等待收到的时长 == `nightChatGap`（4s）；生产构造（`New()`）不得预置注入

## 四、影响分析

| 面 | 影响 |
|---|---|
| 上游行为 | 对话之间的 4s 间隔不变；每次任务少一次尾部等待 |
| 风控观感 | 不变（末次等待之后无请求） |
| 测试成本 | `internal/upstream` 单包少付 4s（golden 生成器 + 成功路径用例） |
| 可测性 | 等待次数由 2 条断言（need=1/need=3）钉住，删等待或多删一次都会红 |
