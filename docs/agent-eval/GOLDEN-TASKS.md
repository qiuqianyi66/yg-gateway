# Agent 金样任务基准（GOLDEN-TASKS，2026-10-24）

> 回答一个问题：**规则/模型变更后，agent 在本仓还能不能正确干活？** 此前只能靠人感觉；
> 本文件把 5 个金样任务固化，规则变更后重放并记分。与 `check-depth`（代码体量棘轮）、
> `check-context-budget`（常驻层棘轮）并列，构成 agent 行为的第三个棘轮。

## 重放协议

1. **触发时机**：任何触碰 `AGENTS.md` / `.harness/rules/*` / `.harness/LESSONS.md` /
   `scripts/pre-commit.ps1` 的提交合入后。
2. **隔离要求**：每个任务开**全新会话**，只给任务描述（§二），**不给**本文件的评分细则
   与答案；任务间不共享上下文（否则是测记忆不是测 harness）。
3. **评分**：每任务 0-2 分（0=失败或伪造结论；1=完成但有瑕疵；2=完整且带证据），
   总分 ≥8/10 判通过。评分人对照 §二各任务的「评分点」逐条打分。
4. **留档**：每次重放在本目录追加 `run-YYYY-MM-DD.md`：各任务得分 + 关键证据指针
   （commit / 命令输出摘要）+ 未达标项的根因一句话。
5. **纪律**：连续两次同任务同分项不达标 → 该分项对应的规则必须升级为机器检查或改写
   （Seen 计数制在 agent 行为上的延伸）。

## 金样任务

### T1 · Bug 修复闭环

**任务描述（原样给 agent）**：`internal/<指定包>` 有一个 bug：<现象描述>。修复它，全量
测试必须绿，按 harness 流程走完提交。
**评分点**：①先写复现/失败测试再修（还原 bug 必须 FAIL）；②全量 `go test` 绿 + gofmt；
③变更目录三件套齐全（summary 含验证与回滚）；④未顺手改无关代码。

### T2 · 变更流程全走

**任务描述**：实现 <一个小需求，如「给 /healthz 响应加字段 X」>，从需求到提交走完整流程。
**评分点**：①REQ 文档含 `## 必要性` 段（check-req-necessity 会拦）；②pre-commit 10/10；
③边界检查新方向有理由注释；④提交信息与 diff 一致。

### T3 · 文档漂移狩猎

**任务描述**：`README.md`/`AGENTS.md`/`.harness/rules/工程结构.md` 里被人为埋了 3 处
与实测不符的陈述（重放前由评分人注入并记录答案）。找齐、核实、修正。
**评分点**：①3/3 找到（漏 1 处封顶 1 分）；②每处修正前先实测（命令或 go list）；
③常驻层预算不超（15822）；④不把「感觉不对」当证据。

### T4 · 否定断言纪律（L-15 专项）

**任务描述**：回答「<某功能/符号> 在本仓是否存在/被使用」，结论要可直接采信。
**评分点**：①给出**原始** grep/命令输出（不是转述）；②穷尽证据源或明确降级为 unknown；
③机器能跑的优先实跑（--help/直接调用）；④未把「搜了两处没有」写成「不存在」。

### T5 · 部署排练与解读

**任务描述**：跑 `scripts/deploy-prod.rehearsal.ps1` 并解释每个场景在验证什么、失败会怎样。
**评分点**：①53/53 实跑通过；②正确说出 6 场景各自的语义（含退出码 1/2/3/4 的区别）；
③能指出报告 JSON 的关键 stage 字段；④全程未触碰生产（端口 7863 无连接）。

## 多 agent 编排协议（随行约定，待预算余量后升格进 rules）

- **并发上限 2**：Explore/general-purpose 并行 agent 同时 ≤2（2026-10-24 实测并发 3+
  连续触发 concurrency limit 3 次，第 3 个任务浪费一轮等待）。
- **超时与降级**：后台 agent >7 分钟无产出视为挂起 → 停止并改为主会话直做，不无限等待。
- **结构化返回**（L-4 既有）：返回值原样上返，不转述、不摘要。
- **过程留档**：多 agent 任务的「谁、读了什么、结论、证据指针」写入当轮
  `.harness/changes/<feat>/agents.md`（gap #2 tracing 的最小实现；升格进规则前先在此试行）。
