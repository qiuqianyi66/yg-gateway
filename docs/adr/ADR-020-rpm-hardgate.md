# ADR-020：出站 RPM 硬闸——机制与默认值解耦，RoundTripper 层挂载

> 状态：**已实施**（P1-1B，`081e200` + 生产部署）。
> 依据：REQ-yg-gateway-rpm-hardgate-2026-11-04 + magpie REA 节奏面（rpm.go:44
> 60s+1s 滑动窗，observation）。
> 决策点：机制 vs 默认值、挂载层、分桶键、窗口满语义、默认值。

## 背景

REA ④可借鉴清单 P0 最高优先级：magpie 出站前强制 RPM 槽位防「短时间把号打热」。
yg 此前已存在 `pool.min_request_interval`（选号侧间隔，8 天 request-logs 观测支撑
默认 0 关）。两者**不是同一件事**，曾被我并入「校准 0 关」轻率闭合（见 LESSONS
L-26），补审后重开为独立机制项。

## 候选对比

### D1：机制 vs 默认值

- 候选 A：把「RPM 硬闸机制」并入 min_request_interval 校准结论（默认 0 关 = 不需要机制）。
  **否决**：校准只观测了「默认 0 关下 429 极低」，不能推出「机制不需要」；打开配置时
  没有任何强制槽位可用。否定断言未穷尽证据（L-22/L-26）。
- 候选 B（采用）：**机制落地为可配置能力（默认 0 关）**，与校准结论解耦——默认值
  回答「今天开不开」，机制回答「要开时有没有」。8 天数据仅支撑前者。

### D2：挂载层

- 候选 A：调用点逐个加闸（chat/billing/models/签到各写一段）。
  分散、易漏新增路径。**否决**。
- 候选 B：**RoundTripper 层统一挂载**（newUpstreamHTTP 包 rpmRoundTripper）——
  直连 HTTP/ChatHTTP + per-proxy clientForProxy 全路径自动覆盖；开关在 RoundTrip
  时判（RpmPerAccount>0 才限速），装配期零值=关闭安全。**采用**。

### D3：分桶键

- 候选 A：X-Machine-ID（账号稳定标识，headers.go 全出站注入）。账号间互异、跨重启
  稳定，是上游风控眼里「设备」维度——限速目标正是「单设备不要打热」。**采用**。
- 候选 B：X-Session-ID（进程级随机，重启即换）。随进程重启清桶，限速窗口跨重启失效。**否决**。
- 候选 C：全局单桶。一个号被限拖累全池。**否决**。
- 无头请求（防御兜底，理论不发生）归 global 桶，受同一配置约束，不绕过硬闸。

### D4：窗口满语义

- 候选 A：阻塞等待最早槽位滑出（magpie 同语义）。请求最终发出，不失败、不换号；
  ctx 取消即返回错误交由既有换号路径。**采用**。
- 候选 B：直接 429/503。把上游限速转成客户端可见失败，无益于养号。**否决**。

### D5：默认值

- 0 = 关闭（零回归）。与 min_request_interval 同口径（负值钳 0）。
  开多少由运维按账号规模定，面板无默认值承诺（unknown，requires 生产打开后的观测）。

## 合同

- 每账号（X-Machine-ID）60s 滑动窗口最多 `upstream.rpm_per_account` 个出站请求；
  请求间最小 1s 槽位（平滑突发，长 SSE 只占 1s 槽不饿死队列）。
- 窗口满：阻塞等待，ctx 取消返回 `ctx.Err()`，不悬挂。
- `RpmPerAccount<=0`：直放，零回归。装配期字段（需重启）。
- wrapper 透传 `CloseIdleConnections`（client.go:710 清池能力不回归）。

## 副作用与回滚

- 关闭态无行为变化（默认 0）；打开后出站可能因限速延后（预期行为）。
- 回滚：删 rpm.go + 配置字段/装配一行 + 测试还原（见变更记录 summary）。
