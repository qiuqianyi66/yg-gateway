# ADR-028：面板视觉方向改为「分区色相 + 轻渐变」（部分取代 app-screen 扁平禁令）

- 状态：已接受（2026-11-20）
- 取代：`docs/plans/2026-11-14-multi-provider-gateway.md` §「只吸收 app-screen 禁令」中
  「不叠渐变 / 不用彩色方块图标 / 按钮纯色」三条；`.harness/changes/panel-visual-flat/summary.md`
  记录的对应规则同步作废。
- 保留：app-screen 禁令里仍然有效的部分——不做霓虹外发光、不做极光 / 3D 粒子背景、
  不做渐变文字、不做跟随指针的光斑（这些在 2026-11 的多轮评审里被明确拒绝）。

## 背景

2026-11 早期，面板按 taste-skill 的 app-screen 规则做过一次扁平化（`panel-visual-flat`）：
删掉 `--accent-gradient`、页面级装饰渐变、按钮渐变，理由是「仪表盘重复面板是常态，
渐变 / 发光 / 彩色方块图标不是」。

此后用户连续四轮反馈「颜色太单调、不够美观、要学大网站」，并明确要求先调研 GitHub 上
优化 AI 前端的仓库（react-bits 51.9k★、magicui 23.1k★ 等）与本地审美 skill。调研结论：
这些库全是 React + Framer Motion + Tailwind，本项目是 go:embed 纯 CSS/JS 单二进制，
**不能直接引入**，只能蒸馏手法（1px 细边、色相身份、骨架 shimmer、渐进入场）。

## 观察（2026-11-20 实测）

- 9 个视图共用一支品牌绿，切页无身份差；卡片是白底 + 1px 灰边，首屏层级只靠字号。
- 参考实现（Linear / Vercel / Stripe 控制台）的共性：**极浅色相分区**（不是大面积渐变）、
  1px 细边 + 极浅阴影、卡片头一层 4–10% 的色底、顶栏玻璃质感，而不是彩虹渐变。
- 约束：`app.css` 已 999/1000 非空行（`check-depth` 的 `oversizeFrontendFiles` 只许收紧），
  新视觉层必须独立成文件；`app.js` 冻结在 1368 行，任何跟随指针 / 逐卡动画都要新 JS 文件。

## 决策

1. 新增 `internal/panel/aesthetic.css`，承载视觉增量；`app.css` 不动。
2. 允许的装饰，且只允许这些：
   - 每个视图一支 `--sec` 分区色相（9 支），挂在 `body:has(可见视图)` 上全页继承；
   - 卡片头 10% 色相微染 + 标题前 5px 方块；卡片顶部 1px 渐变色相线；
   - 视图顶部 13% / 7% 双层径向 wash（单屏可见面积 < 30%，不遮内容）；
   - 顶栏 `--glass` + blur 14px、底部 2px 强调线随视图变色；
   - `button.primary` 竖向轻渐变（同色系 8% 明度差，不跨色相）；
   - 切视图整页 260ms 淡入 + 卡片 400ms 上浮（只挂静态节点，轮询不重播）。
3. 仍然禁止：霓虹/外发光、极光与 3D 粒子背景、渐变文字、跟随指针光斑、跨色相渐变按钮、
   大面积（>50% 屏高）装饰渐变。
4. 语义色优先：`good/warn/bad` 永远压过分区色相；分区色相只表达「在哪一页」，不表达好坏。
5. 无障碍：`prefers-reduced-motion` 下入场动画与加载线动画退化为静态；焦点环 2px 常显。

## 后果

- 视觉记录不再自相矛盾：新的冲突以本 ADR 为准，`panel-visual-flat` 与旧计划里的三条禁令
  视为历史。
- 零运行时依赖、零新增 JS 依赖（加载指示复用 `fetch` 包装，独立 `app_progress.js`）。
- 深浅两套主题都要按新方向核对；暗色下阴影改以描边为主（暗底阴影会糊成黑块）。
- 后续若要做布局级重排（侧栏 / 卡片密度），仍受 `maxFrontendLines`（app.js 1368）与
  `maxFileLines`（app.css 999）两道棘轮约束，需先拆文件，单独立项。
