## 1. 逐项裁定

### A4 — 20 条 per-model `supports_images` 逐条实测

| 四问 | 答案 |
|---|---|
| ①真实问题 | 20 个模型的"支持图片"是**目录声明**（declaration），只有 2 个有真实带图调用证据 |
| ②不做会怎样 | 用户按视觉挑了一个声明支持、实际不支持的模型 → 请求返回**明确错误**（不是静默出错），可换模型重试 |
| ③现状是否已变 | 面板已按三值处理（缺失 ≠ 不支持），筛选不会误排除；声明值全为 `true` |
| ④更便宜手段 | **有**：把「未实测」登记为 unknown（已有 registry），首次视觉请求失败时自动留下观测；批量实测 20 次调用的收益只是提前发现一个会报错的模型 |

**结论：降级做 → 不做全量实测**。理由：危害**可见且可恢复**（报错 ≠ 静默劣化），而 20 次调用换来的只是提前几小时的故障发现。
重评条件：出现「用户投诉图片请求失败」或面板要展示 vision 能力徽章（那时声明必须升级为观测）。

### A5 — `internal/server` 沙箱两份手工同步副本

| 四问 | 答案 |
|---|---|
| ①真实问题 | 两份 324/320 行文件靠**人记**同步；漏同步的那份包会静默失去环境隔离（测试照跑，不再隔离） |
| ②不做会怎样 | 静默失效，**不报错** —— 正是本仓最在意的失效形态 |
| ③现状是否已变 | **没变**：实测两份文件归一化后仍只差 `TestMain` 3 行（`package`/沙箱前缀/日志前缀可白名单） |
| ④更便宜手段 | **有，且比原方案好**：原方案"抽公共包"被文件顶部注释**明确拒绝**（零新依赖 + 边界白名单 + 23 包口径会漂移）。改成一个测试断言两份文件同步即可 |

**结论：做（降级版）**——新增 `TestSandboxFilesInSync`（`internal/pool/sandbox_parity_test.go`），
把"靠人记"换成机器核对。已实施 + 牙齿验证（往任一文件加一行 → 必红）。

### A6 — 变异核验未穷尽（panel 5 条 / autotask 20 分片 / taskcenter 终态）

| 四问 | 答案 |
|---|---|
| ①真实问题 | 已知 10 条变异被钉住，不代表分支被穷尽 |
| ②不做会怎样 | 未覆盖分支的回归不会被测试抓住（**但测试本身也没有覆盖它们**，变异核验只是"证明已有测试有牙齿"） |
| ④更便宜手段 | 有：**按改动触达补**——改哪条分支就先给它做一次变异核验，而不是全仓穷尽 |

**结论：等条件**。重评条件：某个分支即将被改（尤其选号/熔断/任务终态这类承重墙），改之前先补该分支的变异核验。

### A7 — `runAutoAll` 与队列路径「达标未领」处理不一致

| 四问 | 答案 |
|---|---|
| ①真实问题 | 两条路径行为相反：一条跳过不领、一条入队去领 |
| ②不做会怎样 | 可能有一批"达标未领取"的任务长期没人领 → **积分过期浪费**（静默、涉及钱） |
| ④更便宜手段 | 无：这是产品语义，改任一边都会改变后台调用量 |

**结论：等条件（卡 D3）**。解锁动作：用户一句话定语义（统一"入队去领"或统一"跳过不领"）；解锁后 2h 可完成。

### A9 — `cmd/login` 的 4xx 归类 / `server/anthropic.go` 的 stream 类型错被吞

| 四问 | 答案 |
|---|---|
| ①真实问题 | 旧记录说"4xx 全归登录未完成"、"stream 类型错被吞" |
| ③现状是否已变 | **两半都已变**：①`cmd/login/main.go` 的 4xx 分支把**状态码**带进提示（401/403 = 凭证/授权被拒，重来无意义），并有注释说明"不能一概说登录未完成"+ 测试约束（`must NOT contain "http_error: upstream 401"`）；②`anthropic.go` 已返回 `note` 留痕，注释明确"旧实现 `_ = json.Unmarshal` 静默吞掉"是已修的缺陷 |
| ④更便宜手段 | —— |

**结论：不做**。这不是待办，是**文档债**（旧记录把已完成的修正当成遗留写了两次）。
若仍想改 401 的**分支选择**（把 401 走上游错误档），那是**行为变更**，需单独 PRD + 冒烟 = D2，与"修缺陷"不是一件事。

### D4 — 生产备份清理（42 份 `.bak` / 421.7 MB）

| 四问 | 答案 |
|---|---|
| ①真实问题 | `D:\yg-gateway` 堆了 **42 份 `.bak`**（含 `config.json.bak`；把 `yg-gateway.exe.tmp` 也算上是 43 份 / 431.5 MB —— 两种口径都对，写文档时必须带口径） |
| ②不做会怎样 | 占盘 **421.7 MB**；而 D 盘 **空闲 329.4 GB**（占可用空间 **0.13%**） |
| ③现状是否已变 | 每次换版自动新增一份，长期会慢涨 |
| ④更便宜手段 | 必要性本身不成立：删掉的是**唯一回滚来源**（R15 的物证），换 0.13% 空间 |

**结论：不做**。重评条件：D 盘空闲低于 20GB，或单目录备份超过 2GB。
（若将来要做，正确形态是**在 `deploy-prod.ps1` 里做保留策略**——保留最近 N 份 + 里程碑，而不是手工删。）

### D5 — 7864 eval 实例去留

**结论：不做（仅文档已更正）**。实例没在跑，`HANDOFF.md` 已改为"历史记录"；删配置的唯一收益是少一个文件。
重评条件：要用 eval 做真机对照时先复活，走 ADR-005 的验证脚本。

### O1 — `app.js` 4378 行 + `index.html` 1755 行（非空）都曾不在任何体量门禁内

| 四问 | 答案 |
|---|---|
| ①真实问题 | `check-depth.ps1` 只扫生产 `.go`（`-Filter *.go`），前端体量**零约束**，可以无上限增长 |
| ②不做会怎样 | 继续涨；但**不撤**任何东西 |
| ④更便宜手段 | **有**：把前端纳入度量 + 冻结当前值（只许降），约 25 行；**比起拆分文件**（结构性改动 + 无浏览器 E2E 兜底）风险低两个数量级 |

**结论：做「纳入度量」这一半，不做「拆分文件」**。已实施两个指标：`maxFrontendLines`（基线冻结 **4378**）
与 `oversizeFrontendFiles`（>1000 非空行的前端文件数，基线 **2** = app.js + index.html）——只盯最大值会
遮住"第二名变胖"，所以两者都要。
> **本条曾被独立复审判 FAIL 一次**：初版只扫 `*.js`，把 1755 行的 `index.html` 漏在门外，
> 而我自设的重评条件「任一前端文件超过 1000 行」在落地当天就已经不成立。现在扫描面 = js/html/css，
> 且用"超限文件数"兜住第二名。牙齿验证：app.js 加一行 → `REGRESSED: maxFrontendLines 4378 → 4379`。
拆文件的重评条件：出现浏览器级 E2E（Playwright）兜底之后。

### O2 / O3 — 超长测试文件、超长生产文件拆分

**结论：不做**。棘轮（`oversizeFiles 5` / `oversizeFuncs 7`）已经把它们**冻结**——不会再长，只允许变短。
"它们很大"不是缺陷，"它们还在变大"才是；后者已被门禁拦住。重评条件：下一次要改这些文件时，顺手拆一个。

### O4 — 覆盖率棘轮与 panel 测试抖动

**结论：不做**。当前 `minCoverage 72.3%` 稳定通过；先解决"抖动"再谈提覆盖率，而抖动只影响耗时不影响结论。
重评条件：panel 单轮测试超过 2 分钟，或出现因抖动导致的假红。

### O5 — `HANDOFF.md` 672 行瘦身

| 四问 | 答案 |
|---|---|
| ①真实问题 | 交接文档把完成态历史与现行约束混在一层，新会话读得慢 |
| ④更便宜手段 | **有**：`docs/PLAN-open-items-2026-10-17.md` 已经是"未完成事项的唯一入口"，HANDOFF 只需**加一行指针**，不必搬运历史 |

**结论：降级做 → 只加指针**（本轮已在 PLAN §9.4 记录该建议；HANDOFF 的搬运留给下一个真正需要它的会话）。

### 生产换版（当前生产二进制落后源码 2 个提交）

**结论：等条件**。落后的是 `app.js` 的函数抽取（渲染行为零变化）、门禁脚本与文档 —— **没有任何行为变更**。
为一次纯重构停服几秒不划算。重评条件：下一个**有行为变更**的批次一起上（那时换版必要性 = 功能上线）。

### D2（401 是否走上游错误档）/ D3（达标未领语义）

**结论：等条件（用户拍板）**。这两条都不是技术判断，是产品口径；改任一边都会改变对外语义或后台调用量。
