> 定义"东西放哪里"。与 `编码规范.md`（怎么写代码）、`开发流程规范.md`（怎么走流程）配套。AGENTS.md 是总入口。

## 使用方式（触发条件）

# 一、仓库根目录

```
yg-gateway/
├── cmd/                     # 可执行入口（各自独立 main）
│   ├── server/              #   主服务（网关 + 面板）★ 唯一长期维护入口
│   ├── login/               #   CLI OAuth 登录
│   ├── signin/              #   CLI 批量签到
│   ├── credit/              #   CLI 积分日报
│   └── trial/               #   上游试用探测（诊断用）
├── internal/                # 内部包（禁止外部 import）
│   ├── auth/                #   凭证解析 / 原子写回 / realm
│   ├── httpauth/            #   Bearer 鉴权原语（常量时间比较）
│   ├── livecfg/             #   配置热生效快照
│   ├── logfmt/              #   日志脱敏与安全标签
│   ├── panel/               #   Web 面板（index.html + app.js + API + 任务）
│   ├── pool/                #   账号池（选号/冷却/熔断/持久化）
│   ├── prompt/              #   系统提示词体系
│   ├── redisstore/          #   Upstash Redis 镜像（可选）
│   ├── reqlog/              #   请求指标 JSONL 归档
│   ├── scheduler/           #   定时任务（签到/旅行/活跃/保活/夜猫子）
│   ├── server/              #   HTTP handler（/v1/* /status /healthz）
│   ├── session/             #   会话粘性路由
│   ├── upstream/            #   上游客户端（协议/指纹/改写/脱敏）
│   └── usage/               #   用量统计
├── scripts/                 # Python 诊断脚本（probe_active / probe_max_tokens）
├── docs/                    # 文档分层（见 §四）
├── .harness/                # AI 编码治理体系（rules / wiki / changes / skills）
├── .github/workflows/       # CI（go-binaries / docker-ghcr）
├── auths/                   # 凭证（明文 token）🔴 禁提交
├── data/                    # 运行时状态（state/usage/归档）🔴 禁提交
├── config.json              # 实际配置（含 api_key）🔴 禁提交
├── config.example.json      # 配置参考（占位符，入库）
├── persona.md               # 人格提示词（= 破甲法的人格位）
├── lock-auths.ps1           # 凭证 ACL 加固（Windows 必需）
├── start.bat / stop.bat / status.bat
├── yg-gateway.exe           # 构建产物 🔴 禁提交
├── AGENTS.md                # AI 协作规则总入口
├── README.md                # 项目文档
├── go.mod / go.sum
├── Dockerfile / docker-compose.yml
└── LICENSE
```

**边界规则**：
- 🔴 密钥文件（`auths/` / `config.json` / `data/` / `*.exe`）禁提交，只读 `config.example.json`。
- 🔴 构建产物禁编辑禁提交（`.exe` 由 `go build` 生成）。
- 🟢 `persona.md` 可提交（不含密钥，是提示词资产）。

# 二、internal 分层与依赖方向

```
        cmd/server  ─────────────┐
                                 ▼
                            server (HTTP 层)
                            /      |      \
                           ▼      ▼       ▼
                        pool   session   usage
                          |       |
                          ▼       ▼
                       auth ← upstream
                                 |
                                 ▼
                          (copilot.tencent.com)

        panel ──► pool / scheduler / upstream / reqlog / usage （只读+运维动作）
        scheduler ──► pool / upstream
```

**依赖规则**：
- 🔴 `internal/*` 之间不得循环依赖（当前为 DAG，新增包时确认）。
- 🔴 只有 `cmd/*` 可以 `func main()`；业务逻辑一律进 `internal/*`。
- 🟢 `upstream` 是唯一出站口：所有上游 HTTP 调用集中在此，禁在其他包直连。
- 🟢 `auth` 是凭证唯一持有者：token 读写必须经其加锁方法（禁直读字段）。

# 三、面板前端（internal/panel/）

```
internal/panel/
├── index.html          # 页面骨架（含内联 CSS 设计令牌）
├── app.js              # 全部前端逻辑（独立文件，为启用严格 CSP）
├── index.go            # go:embed + 安全响应头
├── panel.go            # /panel/api/* 只读与账号运维
├── autotask.go         # 成长任务自动化（17 任务判据事件链）
├── taskcenter.go       # 任务中心视图 API
├── tasks.go            # 任务列表/接受/领取
├── login.go            # 浏览器内 OAuth 设备授权
├── import.go           # cockpit 凭证导入
├── config.go           # 配置在线编辑（热生效）
├── ring.go             # 运行日志环形缓冲（分频道）
└── frontend_test.go    # 前端结构测试（node vm 执行）
```

**前端约束**：
- 🔴 资源经 `//go:embed` 打进二进制：**改 JS/HTML 后必须重新编译才生效**。
- 🔴 CSP 为 `default-src 'none'`：禁内联脚本/内联事件处理器，脚本只能来自同源 `app.js`。
- 🔴 所有用户输入渲染前必须过 `esc()`（转义 `& < > " '` 五字符）。
- 🟢 前端测试用 `node` + `vm` 执行代码切片（见 `frontend_test.go` 既有范式）。

# 四、docs 分层

```
docs/
├── prd/                 # 需求分析（PRD 级，F-编号 + Given-When-Then）
├── plans/               # 方案与计划（PLAN-*，D-编号决策）
├── adr/                 # 架构决策记录（ADR-NNN）
└── reference/           # 参考（上游协议逆向 / 端点清单）
```

**文档纪律**：
- 🟢 需求先于方案：先 `docs/prd/` 后 `docs/plans/`。
- 🟢 ADR 三条件全满足才写：①难逆转 ②没上下文未来读者会困惑 ③真实权衡（有替代方案且选了一个）。
- 🟢 术语定了当场写 `.harness/wiki/glossary.md`，不批量补。

# 五、.harness 治理

```
.harness/
├── rules/               # 规范（开发流程 / 工程结构 / 编码 / 技能）
├── wiki/                # 项目知识（业务模型 / 数据模型 / API 契约 / 术语）
├── changes/             # 变更追踪（{feat}/summary.md + review.md [+ 迁移]）
└── skills/              # 技能（main-dev 主流程 / biz-dev 业务专项 / ops 运维）
```

- 🟢 每次改动建 `.harness/changes/{feat-name}/`，分支同名。
- 🟢 无数据库迁移时删除 `db-migrations.sql` / `rollback.sql`（本项目无 DB，state.json 是文件态）。
