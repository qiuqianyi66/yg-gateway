# 编码规范（YG Gateway）

> 定义"怎么写代码"。与 `开发流程规范.md`（怎么走流程）、`工程结构.md`（东西放哪里）配套。
> 红线从 tea 项目 15 条裁剪而来，按 Go 单仓库 + 上游逆向网关的实际调整。

---

# 一、红线（🔴 零违反）

| # | 红线 | 判据 |
|---|---|---|
| R1 | **凭证不出 `auths/`** | accessToken/refreshToken 禁入日志、禁入 `state.json`、禁入归档 JSONL |
| R2 | **日志脱敏** | 日志行禁含 Authorization 头、提示词正文、响应正文；UID 只取前 8 位 |
| R3 | **无裸 `innerHTML` 拼用户输入** | 所有变量插 HTML 前必须过 `esc()`；属性插值尤甚（引号闭合可注入事件处理器） |
| R4 | **路径穿越防护** | 任何用用户输入拼文件路径处必须白名单校验（UID `[A-Za-z0-9_-]` ≤64） |
| R5 | **密钥常量时间比较** | 鉴权比较一律走 `internal/httpauth`，禁 `==` 比较密钥 |
| R6 | **出站请求集中 `upstream`** | 禁在其他包直接 `http.Post` 到上游；所有出站改写走统一管线 |
| R7 | **凭证读写加锁** | token 读写经 `auth` 的加锁方法（`AccessTokenValue()` / `RefreshTokenValue()`），禁直读字段 |
| R8 | **上游协议数据不得随意改名** | `wb2api-<ms>` 形式的 conversationId、`chatcmpl-wb2api` 哨兵属于报文内容，改名有风控风险 |
| R9 | **goroutine 有回收路径** | 起 goroutine 必须有 ctx 取消或明确退出条件，禁裸 `go func()` 无回收 |
| R10 | **错误不静默吞** | `err != nil` 必须处理或显式注释为何忽略；禁 `_ =` 吞掉业务错误 |
| R11 | **配置热生效字段标注清楚** | 改配置结构时明确该字段是「热生效」还是「需重启」，面板保存后提示对应文案 |
| R12 | **定时器不泄漏** | `time.Ticker` / `time.Timer` 必须 `Stop()`；长生命周期循环配 ctx |
| R13 | **前端改必重编译** | 改 `app.js` / `index.html` 后必须 `go build`（go:embed），否则线上不生效 |
| R14 | **构建工具链 ≥ Go 1.27.2** | 更低版本带标准库漏洞（HTTP/2 + TLS），禁用于产出二进制 |
| R15 | **二进制替换前备份** | 部署新二进制前保留旧版（`.v{版本}` 后缀），保证可回退 |

# 二、命名

| 对象 | 约定 | Example |
|---|---|---|
| 包 | 小写单词，禁下划线 | `httpauth`、`redisstore` |
| 文件 | 小写，多词用下划线 | `credit_floor_test.go` |
| 导出标识符 | PascalCase | `ServiceName`、`VerifyBearer` |
| 未导出 | camelCase | `creditsEarliestExpiry` |
| 常量组 | 语义前缀 | `bindPrefix`、`stateKey` |
| 接口 | 单方法用 `-er` 后缀 | `Store`、`Closer` |
| 前端变量 | camelCase；常量 UPPER_SNAKE | `EXP_FRESH_MS` |

- 🟢 包名避免与标准库冲突；`internal/` 下包名即目录名。
- 🟢 前端 DOM id 用语义名（`expBox` / `btnExp`），禁 `div1` 这类。

# 三、错误处理

```go
// 🟢 正确：包装错误保留上下文
if err := c.RefreshToken(a); err != nil {
    return fmt.Errorf("refresh token uid=%s: %w", a.UID, err)
}

// 🔴 错误：吞掉或丢失上下文
_ = c.RefreshToken(a)
return err
```

- 🟢 用 `%w` 包装（保留 errors.Is/As 能力），禁 `%v` 拼接丢失链。
- 🟢 业务错误分类集中：上游错误一律经 `Classify`（见 `internal/upstream`），禁各处散落状态码判断。
- 🟢 用户可见错误走 `writeErr(w, status, msg)`，禁把内部错误原文直接回给客户端。

# 四、并发

- 🟢 共享状态必须明确锁归属：`auth` 的 `mu` 保护 token 字段，注释写明为什么。
- 🟢 持锁期间不做 IO（网络/磁盘），只做内存读写——`RefreshToken` 已按此设计。
- 🟢 写回前重新校验快照一致性（防并发刷新覆盖），见 `client.go` 的 `atBefore/rtSnapshot` 模式。
- 🔴 禁在持锁时调用会反向加锁的方法（死锁），见 `auth.Realm()` 的注释说明。

# 五、安全

| 面 | 约束 |
|---|---|
| 凭证落盘 | `0o600` + 原子写（tmp + rename）；**Windows 上另需 `lock-auths.ps1` 改 ACL** |
| 日志 | 归档 JSONL 只存元数据；来源 IP/UA 由 `logging.request_client_info` 控制，可关 |
| 鉴权 | `api_key` 为空 = 不鉴权；非空时面板与 API 同口径校验 |
| 响应头 | 面板与 `/panel/api/*` 统一带 CSP / nosniff / DENY / no-referrer / COOP / CORP |
| XSS | `esc()` 转义 5 字符；新渲染函数必须配 payload 注入测试 |
| 路径穿越 | UID 白名单 + `filepath.Join` 后校验前缀 |

# 六、前端（内嵌面板）

- 🔴 无内联脚本、无内联事件处理器（CSP `script-src 'self'` 要求）。
- 🔴 所有动态文本走 `esc()`；`innerHTML` 只用于静态模板 + 已转义插值。
- 🟢 新增渲染函数 → 配一个"有牙齿"的结构测试（还原 bug 必须 FAIL）。
- 🟢 数据缓存与上游调用分离：打开视图不打上游（逐账号实时查会卡死面板），显式按钮才触发。
- 🟢 设计令牌走 CSS 变量（`:root` / `[data-theme]`），禁裸色值散落。

---

# 七、测试

- 🟢 表驱动测试为主（见 `internal/pool` 各 `_test.go`）。
- 🟢 **测试必须有牙齿**：新增修复类测试需验证"还原 bug 后 FAIL"。
- 🟢 前端测试用 `node` + `vm` 跑代码切片（见 `frontend_test.go`），无 node 时 `t.Skip`。
- 🟢 涉及上游协议的测试用 `httptest.Server` mock，禁打真实上游。

# 八、提交前自检清单（26 项精简版）

**通用**
- [ ] `go build ./...` 通过
- [ ] `go vet ./...` 无输出
- [ ] `go test ./...` 全绿
- [ ] `gofmt -l` 无改动文件
- [ ] 新代码有对应测试，且验证过有牙齿

**前端**
- [ ] `node --check internal/panel/app.js` 通过
- [ ] 改了 JS/HTML → 已重新编译二进制
- [ ] 所有用户输入渲染前过 `esc()`
- [ ] 无内联脚本/事件处理器

**安全**
- [ ] 无凭证/密钥进日志或代码
- [ ] 无裸 `innerHTML` 拼用户输入
- [ ] 路径拼接处有白名单校验
- [ ] 密钥比较走 `httpauth`
- [ ] 依赖变动 → `govulncheck` 零告警

**部署**
- [ ] 二进制替换前已备份旧版
- [ ] 配置字段标注了热生效/需重启
- [ ] 变更已写 `.harness/changes/{feat}/summary.md`
- [ ] 端到端冒烟通过
