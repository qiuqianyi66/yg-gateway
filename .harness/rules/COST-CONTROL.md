# 模型成本控制规范（COST-CONTROL）

> 依据 2026-10-15 生产实例（7863）72 小时实测用量制定。凡接入网关的客户端
> （CLI/面板调试台）选模型、写提示词、配默认模型时，一律遵守本规范。

## 一、实测成本分级（72h，2026-10-15）

| 模型 | 积分/百万 token | 72h 积分 | 缓存命中率 | 结论 |
|---|---|---|---|---|
| hy4-preview-f | ~119 | 6,643（67%） | 17.5% | 🔴 最贵，慎用 |
| hy4-preview | ~133 | 3,193（32%） | 7.6% | 🔴 最贵，慎用 |
| deepseek-v4.1-flash | ~1.1 | 101（1%） | 98.7% | 🟢 主力首选 |
| step-5-preview | 0 | 0 | 66.3% | 🟢 免费可用 |
| kimi/glm 系列 | 116~147 | <1 | — | ⚪ 偶发，非主力 |

**铁律**：99% 的积分消耗来自 Hy4 preview 系列（每百万 token 贵约 120 倍），
且其缓存命中率仅 7%~17%（重复 prompt 全价计费）。**任何默认/主力配置都不得
指向 hy4-preview 系列**；除非任务明确需要该模型能力且用户知情同意。

## 二、选模型原则

1. **默认主力**：`deepseek-v4.1-flash`（成本率 ~1.1，缓存命中 ~99%）。
2. **免费优先**：`step-5-preview`（0 积分）适合不要求深度推理的批量任务。
3. **hy4-preview 使用条件**（三者同时满足才允许）：
   - 任务确实需要 Hy4 能力（对比/验证后）；
   - 已向用户说明单次成本约为 deepseek 的 120 倍；
   - 单次会话内复用同一 prompt 以尽量命中缓存。
4. 面板「模型与档位」视图可按**积分倍率排序**挑选低成本模型；调试台下拉
   已显示「模型名 · x倍率 · 免费/优惠标签」，免费模型优先可见。

## 三、提示词与缓存纪律

1. 系统提示词（persona.md）保持精简：只留沟通风格 + 工程原则，单文件 ≤ 20 行。
2. 长上下文任务优先使用缓存命中率高的模型（deepseek）；重复性任务复用同一
   system + 开场，提升 prompt 缓存命中。
3. 默认思考档位按任务需要选择，不做无谓的高档思考（推理 token 计入计费）。
4. 每次请求前自问：这次真的需要贵模型吗？能用免费/低成本模型替代吗？

## 四、监控

- 面板「用量」页查看 `积分/1M Token` 与缓存命中率，异常升高即查模型分布。
- 月度积分预算：在用量页对账；消耗集中在单模型时先按本规范第一条排查。
