# 开发流程规范（YG Gateway）

> 定义"工作怎么走"。与 `编码规范.md`、`工程结构.md` 配套。

## 使用方式

- 🔴 任何开发任务：先过阶段 0（必要性分析），不回答「要不要做」禁入需求分析。
- 按复杂度×风险分诊（Fast=轻量 / Guided=全流程 / Controlled=全流程+先确认），
  阶段 N 的 Quality Gate 未满足禁入 N+1。

# 零、阶段 0：必要性分析（动工前必答）

> 由来：2026-10-17——14 项待办实测后 6 项不做、2 项降级、3 项等条件，实际只动 3 项。
> **「待办清单」不是工作授权，只是一批假设。**

## 0.1 四问（写进需求文档必要性段）

| # | 问题 | 不回答的后果 |
|---|---|---|
| 1 | **要解决的真实问题是什么？**（引观测/日志/用户症状，非"清单上写着"） | 做完发现没人受益 |
| 2 | **不做会怎样？**（可观测性 × 严重度） | 把"能看懂但没危害"当成缺陷 |
| 3 | **现状是否已变？**（旧文档写的"未做/不存在"是否仍成立） | 重复劳动（已发生 ≥6 次） |
| 4 | **有没有更便宜的等效手段？** | 用 3 小时解决 10 分钟的问题 |

## 0.2 结论四选一

| 结论 | 判据 | 落到哪里 |
|---|---|---|
| **做** | 问题真实 + 后果可见有危害 + 无更便宜手段 | 进入阶段 1 |
| **不做** | 问题不存在 / 危害可忽略 / 设计上已明确拒绝 | 写理由与重评条件 |
| **等条件** | 卡外部输入 | 列出解锁动作 |
| **降级做** | 完整方案太重，一小块值得做 | 只做那一小块，写明放弃什么 |

## 0.3 硬约束

- 🔴 不许用「清单上有」当必要性理由——清单是上一轮的假设，会过期。
- 🔴 否定性断言（不存在/从不/全仓搜不到）必须穷尽证据源（见 AGENTS + LESSONS L-15）。
- 🟢 阶段 0 的产出可以只有一段话，但必须在需求文档里看得见——机器校验：
  新增 `docs/prd/REQ-*.md` 必须含 `## 必要性` 段（`check-req-necessity.ps1`）。
- 🟢 结论是「不做」也是交付物：省掉的工作量即收益，但必须写清重评条件。

# 一、十阶段流水线

| 阶段 | 名称 | Quality Gate（退出条件） | Output |
|---|---|---|---|
| **0** | 必要性分析 | 四问有答案 + 四种结论落一个 | 需求文档「必要性」段 |
| 1 | 需求分析 | 需求文档已产出且用户确认：范围边界、F-编号 + Given-When-Then、非功能约束 | 需求文档（PRD 级） |
| 2 | 方案设计 | 细化方案经用户确认（D-编号决策点已拍板），红线冲突清零 | 细化方案 + summary.md |
| 3 | 任务拆分 | 任务粒度 ≤ 4h，依赖关系明确 | 任务列表 + 执行顺序 |
| 4 | 编码实现 | 遵守编码规范，红线零违反，`go build ./...` 0 error | 可编译代码 |
| 5 | 单元测试 | 核心逻辑测试覆盖（含牙齿验证），测试全绿 | 测试报告 |
| 6 | 代码评审 | 评审通过无 🔴 问题；门禁全绿 | 评审记录 review.md |
| 7 | 集成测试 | 端到端链路通过（真实账号/真实上游） | 集成测试报告 |
| 8 | 预发验证 | 独立端口/目录验证通过（含冒烟） | 验证记录 |
| 9 | 上线部署 | 二进制替换 + 备份 + 重启，冒烟通过 | 部署记录 |
| 10 | 线上观测 | 观测期无异常，指标在基线内 | 观测报告 |

## 阶段衔接规则

- 🔴 串行推进：阶段 N 的 Quality Gate 未满足，禁止进入阶段 N+1。
- 🔴 需求分析先行：阶段 1 必须先产出需求文档并经用户确认，才可进入阶段 2。
- 🔴 确认门：阶段 1 需求文档与阶段 2 细化方案均需用户确认后才进入下一阶段。
- 🟢 回退：任一阶段失败，按回滚路线表回到对应阶段重来。

## 流程路径分级

| 级别 | 改动类型 | 流程路径 | 强制 Gate |
|---|---|---|---|
| L0 | 文档 / 文案 / 注释 | 轻量：阶段 1-3 合并，直接阶段 4-5 后阶段 6 快评 | 红线零违反 + 变更追踪 |
| L1 | 面板样式 / 前端展示 | 轻量：同上，但必须 `node --check` + `go build` | 红线 + 语法检查 + 构建 |
| L2 | 业务逻辑 / 接口 / 调度 | 全流程：阶段 0 + 十阶段逐项 | 阶段 1 需求确认 + 阶段 6 评审 + 测试全绿 |
| L3 | 架构 / 数据模型 / 上游协议 | 全流程 + ADR 先行 | L2 全部 + ADR + 迁移往返 |

**小改动判据（L0/L1 轻量路径适用，全部满足才可合并阶段 1-3）**：
1. 无行为变更（改样式/文案/纯文档）。
2. 无接口契约、数据模型、上游协议变更。
3. 改动文件 ≤ 3 个且不触承重墙（选号/冷却熔断/凭证链路/出站改写管线）。
4. 不满足任一 → 走全流程路径。

# 二、分支与提交规范

| 项 | 约定 |
|---|---|
| 特性分支 | `feature/{feat-name}`，与 `.harness/changes/{feat-name}` 同名 |
| 修复分支 | `fix/{issue-or-bug-desc}` |
| 主分支 | `main`（自托管，单人项目可直接提交但需变更追踪） |
| Commit | `type(scope): message`，type 用 feat/fix/refactor/test/docs/chore |

- 🟢 Commit subject ≤ 72 字符，body 讲 why；缺陷修复与功能/测试分开提交。
- 🟢 破坏性改动走 expand-contract：先 expand（新旧并存、CI 保持绿）→ 分批迁移 → contract（旧形式无引用后删除）。

# 三、回滚路线表

| 阶段 | Rollback Strategy | Trigger |
|---|---|---|
| 编码实现 | `git checkout` 丢弃变更 | 编译失败 |
| 单元测试 | 修复代码 + 重跑测试 | 测试失败 |
| 二进制部署 | 回退到上一版二进制（保留备份） | 冒烟失败 |
| 线上观测 | 回退二进制 + 恢复 `state.json` | 观测期指标越基线 |

- 🟢 二进制替换前必须备份：`yg-gateway.exe` → `yg-gateway.exe.v{旧版本}`。
- 🟢 凭证目录独立：`auths/` 不随二进制回滚，删除即不可恢复（需重新 OAuth）。

# 四、代码 review

## 评审维度（6 维）

1. **正确性**：逻辑、边界、状态流转
2. **性能**：并发 / 锁竞争 / 上游请求量 / goroutine 泄漏
3. **安全**：凭证泄露 / XSS / 路径穿越 / 越权 / 日志脱敏
4. **一致性**：与 wiki 接口/数据模型/术语一致
5. **可维护性**：命名、抽象、重复、复杂度
6. **架构合规**：分层、依赖方向、红线

## 问题分级

| 级别 | 含义 | 处理 |
|---|---|---|
| 🔴 阻断 | 红线/安全/数据错误 | 必须修复，禁降级合入 |
| 🟡 主要 | 功能缺陷/性能风险 | 清零后才可过评审 |
| 🟢 次要 | 可维护性建议 | 记录即可 |
| 🔵 提示 | 风格/微优化 | 不阻塞 |

## 评审约束

- 🔴 红线问题禁止降级；🟡 未清零不过评审。
- 🔴 L2 及以上必须有一次独立复审（另一会话 / 子代理 / 他人），且复审者只读。
  自己写的 `review.md` 只能算自评审，不能作为唯一凭据。
- 🟢 评审记录落盘 `.harness/changes/{feat}/review.md`；多轮评审按轮次分段记录，
  不许用新一轮结论覆盖上一轮。
- 🟢 评审-修复闭环 ≤2 轮；第 2 轮仍不过 → 暂停，人工介入。

# 五、提交前验证矩阵

> 🔴 提交前必跑总闸：`powershell -NoProfile -File scripts/pre-commit.ps1`
> 完整清单以 `scripts/pre-commit.ps1` 自身为准，不在此处逐项复制（复制即漂移）。

## 本地与 CI 的分工

| 层 | 在哪 | 覆盖什么 |
|---|---|---|
| 提前发现 | 本地 `scripts/pre-commit.ps1` | 本次改动的 .go 文件 gofmt · R10 新增行 · go build/vet/test · 边界 · 深度棘轮 |
| **最终闸门** | CI `gate` job | 全仓 gofmt · R10 · 边界 · 深度棘轮（失败即红） |
| 功能测试 | CI `test` job | go test · go vet · node --check · govulncheck |
| 竞态检测 | CI `race` job | go test -race（由 CI 独占，本机无 gcc） |

## 改动面 × 本地必跑

| 改动面 | 本地必跑 |
|---|---|
| 任意改动 | `go build ./...` + `go vet ./...` + `go test ./...` |
| 前端（面板 app.js / index.html） | 上列 + `node --check internal/panel/app.js` + 重新编译二进制 |
| 安全相关 / 依赖变动 | 上列 + `govulncheck` |
| 上游协议 / 出站报文 | 上列 + 真实账号端到端冒烟 |
| 治理/文档 | `scripts/pre-commit.ps1 -Fast` |

# 六、完成标准

- [ ] 阶段 0 必要性已落纸（四问 + 一结论）
- [ ] 十阶段 Gate 逐项满足（小改动合并：summary + 红线 + 冒烟不可省略）
- [ ] 分支规范符合（feature/fix + conventional commits）
- [ ] review 通过无 🔴、🟡 清零
- [ ] 变更已追踪（`.harness/changes/{feat-name}/`）
- [ ] 回滚路线明确（二进制备份可回退）
- [ ] 观测期通过（无异常）
- [ ] 治理数字改动已同步 AGENTS.md + 规则文档（漂移当场修）
