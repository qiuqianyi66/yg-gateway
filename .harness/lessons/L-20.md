### L-20｜外部进程的 stdout 与 stderr 必须分开捕获 —— Seen: 1（**会让 17 条测试在 HEAD 上假红**）

- **Seen 1**（2026-10-20，接手治理改动时发现门禁红）：
  `internal/panel` 的 **17 条 `TestAppJS*` 全红**。报错形态看着像断言被改坏或面板代码变了：
  ```
  request filter={"all":[...],"byIP":[...]}(node:41696) [UNDICI-EHPA] Warning: EnvHttpProxyAgent is experimental...
   want {"all":[...],"byIP":[...]}
  ```
  两边 JSON **内容一模一样**，只是 got 里中间插了一行 node 自己吐的警告。
- **根因**：这些测试用 `exec.Command(node, …).CombinedOutput()` 取输出，而脚本用
  `process.stdout.write(JSON.stringify(...))` 输出结果。node 版本/环境变化后，
  它往 **stderr** 多吐了一行 `[UNDICI-EHPA]` 警告，CombinedOutput 把它并进了 stdout，
  于是 `strings.TrimSpace(string(out)) != want` 恒成立。
  代码没坏、测试没写错，坏的是**取数方式**——而它把结论指向了错的地方（误以为面板坏了）。
- **规则**：
  1. 断言一律只建立在 **stdout** 上：用 `Output()`，**不用** `CombinedOutput()`；
  2. stderr 是诊断信息，只在失败时打印（`ExitError.Stderr`）；
  3. 「node 的 stderr 会随版本/环境变化」是常态（实验性特性警告、弃用提示），
     所以第 1 条不是洁癖，是**防环境升级把测试变红**。
- **本轮落地**（2026-10-20）：22 处 `CombinedOutput()` → `Output()`，新增 `nodeDiag(err, stdout)`
  统一打印「stdout + stderr」；并在 `frontend_test.go` 里加了自检
  `TestNodeCallsDoNotMergeStderr`（扫本包测试文件里的 `.CombinedOutput(`，抓到即红，
  已用负向探针验证有牙齿）。
- **为什么没上机器检查**：按 PRD §六 Q4「先跑两周统计真问题再决定加检项」，
  这条守卫先放在 `go test` 里（零新增门禁项）。**第 2 次出现即升级**为
  `scripts/check-harness.ps1` 的检项（候选 [8]：扫全仓 `*_test.go` 里的 `.CombinedOutput(`）。
