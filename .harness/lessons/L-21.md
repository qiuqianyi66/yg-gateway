# L-21：提交只含本任务产生的文件

**Seen 1 · 状态：规则（用户指令 2026-10-20）**

## 一句话

一个提交（或一次 `git add`）只应包含**本次任务 / 当前对话自己产生或修改**的文件。工作树里
**凭空出现、并非你创建或编辑**的文件（来自另一个对话、另一个进程、或用户并行编辑器），**不要
顺手提交**——先确认归属，拿不准就留未跟踪并问用户。

## 实证（2026-10-20）

本对话按用户授权提交治理改动并 push 后，`git status` 突然多出两个未跟踪文件
`.harness/wiki/api-contract.md`、`data-model.md`（时间戳 10:36–10:37，本会话我未写这两个文件）。
它们是另一个对话的产物。用户明确：「是另一个对话的产物，你不用管」。

当时若不加区分地 `git add -A`，就会把**不属于本任务的文件**混进治理提交并推到远端——污染提交
语义、且可能误代他人署名。正确做法：识别来源 → 不提交 → 向用户确认。

## 判据（怎么算「不是本次任务产生的」）

- 本次会话的工具调用里**没有**写/改过它（Write/Edit 无该路径）；
- 它不在你本回合规划的改动清单里；
- 它的修改时间落在你动手之后、且内容明显是另一主题的连续工作。

三条任一命中 → 视为「外部落入」，不纳入本次提交范围。

## 与既有纪律的关系

- 不冲突 `L-11`（测试与依赖它的生产改动同提交）：那是「自己的文件要同提交」，本条规定「别人的文件
  不碰」。
- 与「选择性 `git add` 显式路径、不用 `git add -A`」一致：显式路径天然把外部文件挡在门外，是这条
  纪律的操作落地。
- 门禁层面：pre-commit 不校验「提交范围纯度」（做不到，也不该做），所以这是**人的纪律**，不是机器检项。
