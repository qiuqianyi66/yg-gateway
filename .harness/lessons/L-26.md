# L-26 校准结论 ≠ 机制不需要（默认值 0 关不能推出机制无缺口）

**一句话**：参数校准（如 8 天观测支撑「默认 0 关」）只回答**默认值/阈值**维度；
「机制是否需要」是独立断言，必须分别穷尽证据。把 A 的结论外推到 B 即轻率闭合。

## 场景（2026-11-04，Seen 1）

REA 可借鉴清单映射时，出站 RPM 硬闸（magpie 节奏面 P0 最高优先级）曾被并入
`min_request_interval` 的「校准 0 关」结论一起闭合——理由写成「8 天数据（429 极低）
支撑默认不开，故机制也不需要」。补审（2026-11-04）逐条对照 REA 清单时发现：
**校准只观测了「默认 0 关下 429 极低」，不能推出「打开配置时机制不需要」**——
后者是全新断言（无强制槽位可用），需要分别验证。缺口重开，落地为可配置能力
（`upstream.rpm_per_account`，默认 0 关，`081e200`）。

## 根因

- 把「未观测到问题」（429 极低）当成「机制不需要」（L-15/L-22 的变体：结论范围
  超出证据范围——不是证据不足，是**外推**到相邻但不同的断言）。
- 「默认值」与「机制」是正交维度：默认 0 关 = 今天不开；机制 = 要开时有没有。
  前者回答策略，后者回答能力。

## 规则

1. 校准/观测结论只适用于它实际测量的维度；相邻断言（机制必要性、能力有无）须
   单独穷尽证据（AGENTS.md 否定性断言纪律 L-15 同源）。
2. 补审 REA/清单类映射时，机制项与默认值项分开判定，不合并闭合。
3. 写「不需要」前自问：是「实测不需要」还是「没测到需要」？后者一律 unknown + requires。

## 防法

- 本案例：RPM 硬闸重开为独立 REQ（REQ-yg-gateway-rpm-hardgate）+ ADR-020
  （D1 明确「机制 vs 默认值」候选对比），机制落地为可配置能力（默认关零回归）。
- 后续补审：对每个「闭合/不排期」条目，标注闭合依据是 observation 还是
  inference 外推；外推一律重开核对。
