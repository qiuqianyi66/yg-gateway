# L-27 机制化改造须穷尽调用入口族（主路径 + 独立分支）

Seen: 1 ｜ 族系：与 L-15（否定断言穷尽证据源）、L-22（结论前穷尽证据）同属「穷尽」元主题 ｜ 机器检查：`TestAppJSStandaloneFetchBearer`

## 坑

P1-3「api() 强制鉴权机制化」只审计了 app.js 主路径的 `api()` 调用点，
**独立嵌入文件族**（trends / agent_profile / bench / opsagent / savings_note）各自带
自包含 `fetch('/panel/api…')`，不在 app.js 源码里 → 审计没覆盖。三处漏带
`Authorization`，生产开 api_key 鉴权后用量页两模块 401「未授权」当场显形。

## 判据

做「机制化」改造（强制鉴权 / 统一入口 / 全局替换）时，**穷尽该机制的每一个
调用入口族**，不只主路径：

- grep 该模式在**全部前端文件**（含独立嵌入文件）的出现点，逐个核对；
- 用「凡出现 X 必须 Y」的机器检查钉死（本仓做法：源码断言测试），
  否则漏网当场不红，几周后以用户可见故障显形。

## 修复

三处独立文件补 Bearer（与正确先例 opsagent 同款）；新增
`TestAppJSStandaloneFetchBearer`：逐文件扫描，凡含 `fetch('/panel/api` 必须含
`Authorization`，未来新独立文件漏带即 FAIL。
