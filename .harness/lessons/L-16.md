### L-16｜自评审 PASS ≠ 评审通过；独立复审必须另起一人 —— **Seen: 1 → 已升级为规则**

- **Seen 1**（2026-10-17，`.harness/changes/2026-10-17-necessity-stage-and-parity/`）：
  我先按六维自评审给出 **PASS**、写进 `review.md` 并随改动提交（`5717e20`）；
  随后一个**只读**子代理独立复审，判 **FAIL（0 🔴 / 3 🟡 / 5 🟢 / 6 🔵）**，而且它列的
  3 条 🟡 全是我自评审"检查过且认为没问题"的地方：
  1. 脚本里 4 处 `git` 调用**从不判 `$LASTEXITCODE`**（stderr 还被 `2>$null` 丢掉）→
     `-Base` 写错时脚本以 exit 1 退出，而 pre-commit 会把它归因成「缺必要性段」（误导诊断）；
  2. **`core.quotePath` 默认 true**：`git diff --name-only` 把中文文件名输出成
     `"docs/prd/REQ-\344\270\255...md"`，正则不匹配 → **中文名 REQ 在 CI 静默跳过**。
     本机没暴露，只因为用户级 `.gitconfig` 恰好设了 `false`——「本机绿」来自环境巧合；
  3. 前端棘轮只扫 `*.js`，漏掉 `index.html`（1755 非空行），而我在 summary 里自设的
     「任一前端文件超过 1000 行」重评条件**在落地当天就已不成立**。
- **根因**：自评审看的是"我有没有按自己的设计做到"；独立复审看的是"这个设计在别人的环境里
  还成不成立"。前者天然共享作者的盲区——尤其"本机配置恰好掩盖了缺陷"这一类。
- **规则**：写进 `开发流程规范.md` §四「评审约束」——🔴 L2 及以上必须有一次**独立只读复审**；
  自评审不能作为唯一凭据；复审结论与自评冲突时以复审为准并当场修。`review.md` 按轮次分段，
  **不许用新一轮覆盖上一轮**（要写明「第 1 轮 PASS 已被第 2 轮 FAIL 取代」）。
- **为什么不是机器检查**：「评审者是否独立」无法用脚本判定（同进程跑两次不算独立）。
  能机器化的是它抓到的**缺陷形态**——本轮已把 `-c core.quotePath=false` 与 git 退出码判据
  落进 `scripts/check-req-necessity.ps1` 本体；独立性本身靠规则。
