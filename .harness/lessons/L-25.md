# L-25 go:embed 静态资源 URL 无内容指纹，必须显式 no-cache

**一句话**：资源打进同一个 exe、换版后 URL 不变；没有缓存头时浏览器按启发式缓存旧的
app.js/css——「改了代码、部署了、线上还是旧界面」，第一反应是查缓存，不是查代码。

## 场景（2026-11-04，Seen 1）

游戏化改动提交后线上无成就带。排查链：生产 exe mtime 19:48 早于提交 20:23（第一次真因：
P1 根本没部署）→ 重新部署后用户仍报「加载不出来」（第二次真因：JS 三连崩，见 L-23/L-24）
→ 全修完后，浏览器仍可能加载内存里的旧 app.js（第三次真因：响应无任何 Cache-Control 头）。

## 根因

- 默认假设「我重新部署了就会生效」：go:embed 把文件打进二进制，但浏览器缓存是**客户端**
  的事，与服务端是否换版无关。
- 没有 ETag/版本查询参数做指纹（单文件零依赖设计不允许），唯一解是响应头声明。

## 规则

1. `setSecurityHeaders` 统一加 `Cache-Control: no-cache, must-revalidate`（页面 + JS/CSS/API 同口径）；
2. 报「前端改了没变化」时，排查顺序：部署的 exe 是否含此版本 → 响应头 → 浏览器强刷，
   禁止上来就改代码。

## 防法

- 已落地：index.go `setSecurityHeaders` 加头；部署后 `Invoke-WebRequest` 验证响应头存在。
