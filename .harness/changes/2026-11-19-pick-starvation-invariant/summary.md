## 起因

用户要求重新梳理架构、继续优化算法。测绘结果：

| 包 | 非测试代码行 | 文件数 |
|---|---|---|
| `internal/upstream` | 11232 | 39 |
| `internal/server` | 6703 | 29 |
| `internal/pool` | 4965 | 15 |
| `internal/panel` | 4679 | 18 |

`internal/pool` 是差异化定位第 2 条（养号友好型选号）的实现处，所以从它入手。

**先排除了性能方向**：`BenchmarkPick46Accounts` 实测 **4542 ns/op**（46 个账号选一次 4.5 微秒）。
一次上游调用是几十毫秒量级，选号耗时占不到万分之一。**追性能没有真实空间**，不做。

## 第一处推断错误（我自己）

读 `selectFromCandidates` 的等权重洗牌分支时，我判定它有个缺口：

```go
eq := false
for i := 1; i < len(ws); i++ {
    if ws[i].w == ws[0].w { eq = true; break }
}
```

它只比较**第一名**与其余项，因此我只能推出「非第一名之间的并列检测不到」。我进一步推断：
7 个候选、权重 `[100, 50×6]`、top5 截断后，UID 最大的两个 50 会永久饿死。

**写了测试去证，测试 PASS。推断错了。**

原因是我把权重当成了静态值。`weightOf` 里的闲置补偿项依赖 `lastUsedTime`：

```
w = 1 + credits/maxCredits*10 + min(闲置小时*0.5, 5)
```

账号一旦被选中，`lastUsed` 归零，idle 补偿从 5 掉到 ~0，权重从 6 掉到 1.1，下一轮自然掉出
top5，把位置让给还没用过的并列号。**轮转是设计里本来就有的，不是缺口。**

## 立起来的测试

`internal/pool/pick_starvation_test.go` → `TestPickTiedBelowLeaderNotStarved`

场景：1 个高积分号（权重 16）+ 6 个积分相同、从未使用过的号（权重都精确等于 6.1），跑 3000 轮，
断言 6 个并列号**每个都必须被选中过**。

**这条测试守的不是现状的对，是「别把当前的解药拆掉」**：真正的防饿死机制是闲置衰减，不是洗牌。

### 变异验证（证明它有牙齿）

把 `defaultIdleWeightMax` 从 `5.0` 改成 `0.0`：

```
--- FAIL: TestPickTiedBelowLeaderNotStarved
    pick_starvation_test.go:49: u6 从未被选中（3000 轮）
    counts=map[u1:2214 u2:202 u3:196 u4:196 u5:192]
```

**`u6`、`u7` 恒为 0**，与推断中的饿死形态完全一致——只是触发条件是「关掉闲置衰减」，
而不是「存在非第一名并列」。改回 `5.0` 后复跑 PASS。

## 第二处发现：洗牌分支没有测试保护

**删除测试**：把 `if len(ws) > 5 {` 改成 `if false && len(ws) > 5 {`，跑 `go test ./internal/pool`
全套 —— **仍全绿**。

结论是「删掉它不会有任何测试变红」，即**它不承重**。但「没测试」不等于「无用」：它在
「全员并列、权重完全冻住」的场景下确实能打散 top5 截断次序。

处理：**保留代码，改注释说真话**。原注释声称「等权重账号被字典序饿死」是本分支解决的，
实测不成立（解药在 idle 衰减）。新注释写明：

- 本分支只处理「第一名与其余项权重相等」这一种边界；
- 非第一名之间的并列由闲置衰减解决，并指明哪条测试固化它、怎么让它 FAIL；
- 2026-11-19 记录：删除本分支全套测试仍绿，改它时需要自己确认行为。

## 顺带修的一处文档漂移

`AGENTS.md` 的「变更追踪」章节原本要求每次改动配 `docs/prd/REQ-*.md` + `summary.md`，
而 `check-harness.ps1` 的检项 [6] 实际只查 `summary.md`。

实测：192 个 changes 目录里**只有 23 个带 PRD**（12%）；summary 本身质量反而很好，
192 个里只有 13 个缺「回滚」、4 个缺「验证」。

按 `neat-freak` 的原则（规则和现实不一致时，要么改规则要么改现实，不能放着），
改文档对齐机器判据：**行为/契约变更才配 PRD**，文档修正/补测试/一行修复不配。

写的时候踩了一次预算：第一次加了 4 个包名和一段解释，`check-context-budget.ps1` 报
**14814 > 14805**；压回纯数字替换后为 14805/14805 压线通过。

## 明确没做的

- **没有改选号算法本身**。`pickWeighted` 的定点 int64、`ewmaWeightFactor` 的饿死防护与冷启动
  中性、成本分层硬过滤、`usedSeq` 防时钟精度——都为各自的选择写了理由，我没有找到能证明更优的
  替代，不做「为改动而改动」。
- **没有删洗牌分支**。删了没测试变红，但它有真实作用范围；删是重构不是优化。
- **没有继续拆大文件**（`email.go` 750 行、`state.go` 831 行等）。此前已判定「删除测试不支持，
  只是搬家」并冻结。
