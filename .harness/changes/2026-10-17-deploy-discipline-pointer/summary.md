## 一、必要性

`AGENTS.md` 是「新会话第一件事读本文件」的顶层约束，但它的部署纪律只写了四条原则，
**没有指向 `scripts/deploy-prod.ps1`**——而那个脚本正是这四条的实现（备份、同一条命令、
冒烟、失败回滚）。后果：新会话读到「构建 + 复制 + 启动放同一条命令」，要么手工分步做（正是
2026-10-16 那次实弹前的状态），要么根本不知道脚本存在，于是重复造一遍。

这不是文风问题：**纪律的价值取决于它指向可执行的东西**。原则不落到命令上，就会各自发挥。

## 二、改了什么

保留原四条原则（一字未删），在其后追加：

| 内容 | 为什么 |
|---|---|
| 三条用法命令（`-Exe` / `-Build` / `-DryRun`） | 让「怎么换版」有唯一答案 |
| 脚本固化的流程串 + JSON 报告字段 | 说明它覆盖了哪四件事、留了什么证据 |
| **退出码表 `0/1/2/3/4`** | `1`（已确认旧版在跑）与 `4`（旧版没起来、生产可能不可用）的区别是**操作者唯一能据此行动的信息**，混读会让人带着假安全感离开 |
| `-Build` 遇脏工作区在构建前拒绝 | 2026-10-17 实弹踩过：部署的 exe 不对应任何提交（含并行会话在途改动） |
| 改脚本先跑排练 | 排练在 `%TEMP%` 沙箱跑 6 场景 / 53 断言，不碰生产 |
