## 2. 六轨质量地图

### A. 功能与产品行为

- **范围**：`/v1/chat/completions`（OpenAI）、`/v1/messages`（Anthropic）、面板八视图、账号池/任务中心/opsagent
- **确认强项**：e2e 4 用例全绿（密钥门→登录→八视图→opsagent），连跑 16 次稳定；兼容层有专门测试（`openai_compat_test.go`、`anthropic_bugfix_test.go`）；手工回归脚本 S1–S8 存在
- **主要风险**：浏览器级用例只有 4 个，覆盖的是"面板能开、视图能切"，不覆盖真实对话链路
- **证据缺口**：真实上游调用未在 e2e 中验证（需真账号，属敏感）
- **候选**：无（现有覆盖与该轨风险匹配）

### B. 正确性与可靠性

- **范围**：31 包单测、CI `race` job、goroutine 回收、优雅停机
- **确认强项**：`-race` 由 CI 独占且绿；goroutine panic 隔离有专项记录；alerting 通知重试竞态已修（send 失败 `delete(n.last,key)` 是有意可重试设计）
- **主要风险**：本机无 gcc 跑不了 `-race`，本地改并发代码只能靠设计 + 单测
- **证据缺口**：7×24 长稳无实测；优雅停机只有单测，无真实进程验证
- **已证伪的怀疑**：`scheduler.go:626/697` 的 `RunActivityNow` / `RunKeepaliveNow` 用 `context.Background()` **不是缺陷** —— 623-624 行注释写明它们是「无 ctx 的外部入口（面板/测试一次性触发）」，排程主循环走 530/532 行的 `runActivity(ctx)` / `runKeepalive(ctx)`
- **候选**：无

### C. 安全与隐私 ⚠️

- **范围**：面板鉴权、`internal/httpauth` 常量时间比较、禁 HTTP/2、入站 body 上限、受信任代理防伪造 XFF、凭证 ACL、日志脱敏
- **确认强项**：`TestSecurityHeadersOnAllPanelResponses` 覆盖全部面板路径（含本轮新增的 3 个静态资源）；常量时间密钥比较强制走 `internal/httpauth`；`1c0b89d` 已移除 `allow_unauthenticated` 开关
- **主要风险**：**生产实例跑的是 `1c0b89d` —— 早于 v2.1.0**。v2.1.0 → v2.2.1 之间的安全加固与修复（goroutine panic 隔离、alerting 竞态、e2e 抓到的 `initNotifCenter`、以及后续多条 hardening）**全部未在生产生效**
- **证据缺口**：无成文威胁模型；无渗透测试记录
- **候选**：**C1（见下）**

### D. 性能与成本

- **范围**：选号算法（`BenchmarkPick46Accounts`）、积分成本分层、积分保底
- **确认强项**：选号 4 allocs/op、~5µs（46 账号基准）；成本 tier 有 provenance 标注（inference + samples）
- **主要风险**：**全仓只有这一个 bench**。SSE 转发、面板 API 热路径、请求编排均无性能基线
- **证据缺口**：无生产 p50/p90/p99；`/status` 的延迟分位数是固定分桶插值估算（已在 AGENTS 中标注 derivation）
- **候选**：D1（低优先级，见下）

### E. 架构与开发效率

- **范围**：包依赖方向（23 条 allow 表）、体量棘轮、覆盖率棘轮、治理自检
- **确认强项**：**直接依赖 0 条**（产品定位要求"个位数量级"，实际为零 —— 这是本项目最硬的差异化）；`check-boundaries` 白名单实测生成；体量棘轮三轮收紧（前端 1640→1368）
- **主要风险**：**覆盖率棘轮只统计有测试的包**，4 个 `cmd/` 工具包 0 覆盖却不受约束 —— 门禁的结构性盲区
- **证据缺口**：无
- **候选**：**E1（见下）**

### F. 易用性与审美

- **范围**：面板八视图、暗色主题、通知中心、Ctrl+K 命令面板、空态文案
- **确认强项**：Ctrl+K 18 项命令、通知面板持久化、空态有明确文案（"暂无审计轮"）
- **主要风险**：全部靠自动断言，没有真实用户走查，也没有截图基线
- **证据缺口**：无人工可视评估记录；无响应式/无障碍检查
- **候选**：无（该轨风险等级低于 C1/E1）

## 3. 候选短卡（≤5，按优先级）

### C1 — 生产实例落后 49 个提交（**推荐本批**）

- **痛点证据**：`D:\yg-gateway\yg-gateway.exe` 的 `LastWriteTime` 为 `2026-11-12 16:45:48`；对应提交 `1c0b89d`；`git rev-list 1c0b89d..HEAD --count` = **49**；`git tag --contains 1c0b89d` 显示 `v2.1.0`/`v2.2.0`/`v2.2.1` 都在其**之后**。生产 `/healthz` 返回 `{"healthy":2,"realm_servable":{"cn":true,"global":false},"total":4}` —— 服务本身健康。
- **谁在承受什么**：所有通过 7863 调用网关的用户。这 5 天里的安全加固、panic 隔离、竞态修复**在生产上都不存在**；同时生产跑的东西既不等于发布的 `v2.2.1`，也不等于仓库 HEAD。
- **模块职责 / 依赖**：不适用（运维动作，非代码模块）
- **删除测试**：不适用
- **可观察收益**：生产 = 发布 = HEAD 三者对齐；"真实环境已验证"这一级从**完全缺席**变成**存在**
- **最小方案**：`powershell -NoProfile -File scripts/deploy-prod.ps1 -Build -Feature deploy-2.2.1`
- **影响面 / 风险**：**重启生产服务**（短暂不可用）。属 v10 定义的「外部发布」→ **需授权**
- **回滚**：脚本内置。备份 → 等端口释放 → PE 预检 → 改名替换 → 启动 → 健康轮询 → 冒烟，`finally` 落 JSON 报告。退出码：`0` 成功 / `1` 未生效且旧版在跑 / `2` 健康失败已自动回滚 / `3` 冒烟失败（不回滚）/ `4` **旧版没回来，生产可能不可用**
- **验收判据**：退出码 `0`；`deploy-prod` 报告 `exe_hash_after` 等于本次构建产物；`/healthz` 的 `healthy/total` 与部署前一致；面板 `/panel/` 200

### E1 — 覆盖率门禁存在结构性盲区

- **痛点证据**：`go test ./... -cover` 显示 `cmd/bench`、`cmd/harnessrun`、`cmd/signin`、`cmd/trial` 均为 `coverage: 0.0%`；而 `check-depth.ps1` 的 `minCoverage 78.5` 只在**有测试的包**上计算，这 4 个包因此永久免税。
- **谁在承受什么**：改坏 `cmd/bench` 的三项指标（选号到期偏置 M1 / 池健康度 M2 / 路由成功率 M3）不会有人发现，而这三项是决策输入。
- **模块职责**：`bench` = 纯离线计算（不发起上游调用）→ **最容易测**；`harnessrun` = 金样评分；`signin`/`trial` = 一次性批量运维脚本
- **删除测试**：删掉 → 用户失去离线指标能力，复杂度扩散给人工脚本。**不支持删除**，支持补最小断言
- **最小方案**：只给 `cmd/bench` 补两条断言（空输入不 panic；输出 JSON 字段齐全）。另三个是批量运维脚本，补测试性价比低，明确不补
- **回滚**：删测试文件
- **优先级**：中（不影响运行时，但影响决策可信度）

### D1 — 核心路径无性能基线（低优先级，暂不实施）

- **证据**：全仓唯一 `Benchmark*` 是 `BenchmarkPick46Accounts`
- **为什么不选**：v10 §3 要求「有测量证据的性能热点」才优先。目前**没有任何测量**说 SSE 转发或面板 API 是热点。无基线时只给测量方案，不虚构优化
- **若要做**：给 SSE 转发加 bench，需要先构造 fake 上游；成本高于 C1/E1
