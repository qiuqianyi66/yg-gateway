### 技术方案

**信息层级（D-004 拍板：池子健康总览优先）**

统计条从 7 列等宽改为非对称栅格：

```
改前：repeat(7, 1fr)  —— 7 卡片等大，视线无落点
改后：1.35fr 1.35fr 1fr×5 + .hero/.minor 分级
      hero（34px 大字 + 渐变底）＝ 可用账号 / 积分剩余
      minor（19px 灰字）＝ 总数 / 冷却 / 暂停 / 禁用 / 粘性
```

顺序即问答顺序：**健康吗 → 积分够吗 → 异常在哪 → 细项**。

**到期卡片从文本行改栅格（D-005 沿用快照数据源）**

```
改前：flex 文本行，数字埋在句子中间
      "最近到期 2026-10-31（21 天后到期）· 该批 499 积分 · 日均需耗 ≥24"
      → 扫读要逐行读句子才能比大小

改后：栅格五列成对齐 + 左侧危险度色条
      账号 | 最近到期 | 距到期 | 该批积分 | 日均需耗
      账号A | 2026-10-31 | 21 天 | 示例值 | ≥示例值/天
      → 眼睛沿列走即可直接比较
```

色条替代 9px 圆点：余光可捕获，扫读更快。两份渲染函数（`renderExpiry` 逐包版 /
`renderExpirySnapshot` 快照版）**同步改**并各留一份同文案表头，避免切数据源时列位跳变。

**视觉验证中又抓出的三处问题（真机截图才发现）**

1. **列名歧义**：初版表头是「剩余 / 该批」——第 3 列实际是**天数**（21 天）、第 4 列是
   **积分数**（499），叫「剩余」会被读成"剩余积分"而与第 4 列撞义。改为
   「距到期 / 该批积分」，并把断言钉进测试防回退。
2. **逐行重复提示**：快照版每行都挂"仅最早一批，点「检查」看全部"，4 个账号重复 4 次、
   零信息增量，还把行高从单行撑成两行。删除；该说明卡片头部（`expNote`）已有一次。
3. **日期列左对齐**：日期是"值"不是"标签"，左对齐时列间空白把「2026-10-31」和
   「21 天」这对同一事实的数据拉开。改右对齐，值区连成一片，账号名独占左侧。

## 五、Learning

根因一: 面板信息层级缺失不是"不好看"，而是"读不出结论"——7 个等大卡片让人自己找重点，
到期数字埋在句子里让扫读变成逐行精读。

根因二: 治理规范不写进版本库就等于没有治理。`.gitignore` 的 `*.md` 是从上游继承的
"别提交文档"策略，与本项目要建立的可追溯流程直接冲突；两条策略并存时，被静默牺牲的
总是后来者（这里就是 `.harness/`），因为没人会去怀疑一个"一直这样"的忽略规则。

根因三: 结构改动必须真机验证。列名歧义、逐行重复提示、日期左对齐造成的列间断裂，
在代码层与单元测试里都看不出来（断言只关心结构与转义），只有截图后才暴露。
另：截图验证本身也会骗人——面板 `theme` 默认 `auto` 跟随 `prefers-color-scheme`，
不给 Playwright 传 `colorScheme` 时，两张"不同主题"的图其实字节相同。

根因四（切片契约）: 前端测试用 `indexOf` 定位代码段，因此**函数外的常量**不进切片、
**注释里出现函数声明字面量**会把切片从中间切断。两者都实际发生过：前者让
`EXP_HEAD` 一提出去就 ReferenceError，后者让 `Unexpected end of input`。
共用常量的"重复消除"在这里不成立，重复是这个契约下的必然代价——已在代码注释里写明原因。
