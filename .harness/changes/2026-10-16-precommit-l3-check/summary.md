## 一、改了什么

**只改 `scripts/pre-commit.ps1` 一个文件**：新增检查 4/7，并把其余检查的分母从 `/6` 改成 `/7`
（检查内容与顺序不变，只是插了一项进去）。

### 1.1 检查内容

扫**git 未跟踪**的文件里、位于**仓库根**、名字属于下列形态的：

- 以 `$` 开头（`$out` / `$cov` / `$p` / `$tmp` / `$abs` …）；
- 整体形如 `out` / `p` / `tmp` / `cov` / `cover` / `profile`（允许前导点）。

命中即失败，并打印两行正确写法提示：

```
$out = Join-Path $env:TEMP "cov.out"; go test "-coverprofile=$out"   ← 双引号 + 落 $env:TEMP
```

### 1.2 为什么扫「产物」而不是扫「diff 里的写法」

原候选方案是扫新增行里未加引号的 `-\w+=\$` 形态。改扫产物的理由：

| | 扫 diff 写法 | 扫产物（采用） |
|---|---|---|
| 误报面 | 大：要处理引号、转义、跨行拼接、here-string 内的合法文本 | 零：`$` 开头的文件名在仓库根**不可能**有正当用途 |
| 覆盖度 | 只覆盖模式匹配到的写法 | 覆盖**所有**导致同一产物的写法（含模式外的新写法） |
| 判据强度 | 「你写得不规范」（启发式） | 「你已经在仓库根造了一坨垃圾」（事实） |

这与 L-6 的教训同源：**判据要盯「事实」而不是「写法」**——L-6 是「CI 里查改动文件恒空导致假绿」，
本质也是判据盯错了对象。

### 1.3 刻意收窄的范围（防误报）

- 只看 `git ls-files --others --exclude-standard`（未跟踪），已跟踪文件不管；
- 只看仓库根（名字带 `\` 或 `/` 的一律放过），`data/`、`.harness/` 等子目录不受影响；
- CI 里必然通过（工作区干净、无未跟踪文件）——这不是放水，它要拦的本来就是本地跑覆盖率的手误。

## 二、怎么验证的（TDD：先看到红，再变绿，再验误报）

### 2.1 RED —— 先证明旧门禁会放过这个坑

```
[造出仓库根文件 $out（内容任意）]
powershell -NoProfile -File scripts/pre-commit.ps1 -Fast
→ 提交前检查全部通过。   exit=0     ← 门禁放过了它（这就是 L-3 一直没被机器拦住的证据）
```

### 2.2 GREEN —— 加上检查后必须红并点名

```
负向探针 1（只有 $out）：
  --- 检查 4/7：仓库根的字面名垃圾文件（L-3）
    [FAIL] 仓库根出现字面名垃圾文件: $out
  提交前检查未通过（1 项）： - 仓库根字面名垃圾文件 1 个（L-3）      exit=1

负向探针 2（$cov / $p / out / tmp 四个一起放）：
    [FAIL] 仓库根出现字面名垃圾文件: $cov
    [FAIL] 仓库根出现字面名垃圾文件: $out
    [FAIL] 仓库根出现字面名垃圾文件: $p
    [FAIL] 仓库根出现字面名垃圾文件: out
    [FAIL] 仓库根出现字面名垃圾文件: tmp
  提交前检查未通过（1 项）： - 仓库根字面名垃圾文件 5 个（L-3）      exit=1
```

### 2.3 误报探针 —— 正常的未跟踪文件不得被点

```
仓库根同时存在 工作准则-融入版.md（并行会话的未跟踪文件，无分隔符、位于仓库根）
→ 检查 4/7 的输出里没有它        ← 不误报
```

### 2.4 清理后必须变绿

```
[删除 $out / $cov / $p / out / tmp]
  --- 检查 4/7：仓库根的字面名垃圾文件（L-3）
    [OK]   仓库根无字面名垃圾文件
  提交前检查全部通过。      exit=0
```

### 2.5 全量门禁

```
powershell -NoProfile -File scripts/pre-commit.ps1     # 六项（现七项）全过，exit 0
```

## 三、怎么回滚

```powershell
git revert <本变更的提交>
```

或手工删掉 `scripts/pre-commit.ps1` 里「检查 4/7」整段并把分母改回 `/6`。
本变更不影响生产、不影响 CI 判定语义（CI 里该检查恒通过）。

## 四、边界与后续

- 这条检查**拦不住**「变量没被展开但产物被写到了 `$env:TEMP`」的情形——那种情况下没有
  垃圾产物，也就没有可见危害（profile 落在临时目录是**正确**用法）。
- 同理它拦不住「变量没展开 + 产物被写到仓库里某个子目录」。**这仍是未知**：
  未观察到该形态（已知两次都落在仓库根），若出现第 3 次，再把范围下探到子目录。
